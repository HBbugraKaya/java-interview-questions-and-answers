# What is HATEOAS

---

## 🟢 Junior Level

**HATEOAS** (**H**ypermedia **A**s **T**he **E**ngine **O**f **A**pplication **S**tate) is the defining architectural constraint of **Level 3** in the Richardson Maturity Model, and the purest manifestation of Roy Fielding's vision for REST.

Under HATEOAS, the server returns not merely raw domain attributes, but also a **dynamic graph of permissible next actions** encoded as hypermedia links (`_links`) directly inside the response body.

### Real-World Analogy: Navigating via Web Browser

When you use online banking through a web browser:
- You do not manually type `/accounts/101/transfer-funds` into the browser address bar.
- You inspect your account balance on the screen, and the website renders a clickable link/button: *"Transfer Funds"*.
- If your account is frozen or you lack transfer permissions, the server simply **omits the transfer button** from the rendered HTML.

HATEOAS applies this identical hypermedia interaction model to programmatic machine-to-machine APIs.

---

### Side-by-Side Payload Comparison

#### Standard Pragmatic REST (Level 2):
```json
{
  "orderId": 501,
  "status": "AWAITING_PAYMENT",
  "totalAmount": 250.00
}
```
*Drawback:* The API client must hardcode procedural knowledge in advance: it must know that paying requires `POST /api/v1/orders/501/payments` and cancellation requires `POST /api/v1/orders/501/cancellations`.

#### REST with HATEOAS (Level 3 HAL):
```json
{
  "orderId": 501,
  "status": "AWAITING_PAYMENT",
  "totalAmount": 250.00,
  "_links": {
    "self": { "href": "/api/v1/orders/501" },
    "payment": { "href": "/api/v1/orders/501/payments", "type": "POST" },
    "cancellation": { "href": "/api/v1/orders/501/cancellations", "type": "POST" }
  }
}
```
*Advantage:* The client inspects `_links`. If the order is paid, the server omits the `payment` and `cancellation` links, automatically signaling to the client interface that these actions are no longer available.

## 🟡 Middle Level

### Dynamic Affordances and the Server-Driven State Machine

In HATEOAS, links represent **Affordances (Actionable Capabilities)**:
- The server acts as a **Finite State Machine (FSM)**.
- Permissible transitions between lifecycle states are governed entirely by the server, not hardcoded into client logic.
- **Dynamic Access Control (RBAC/ABAC):** If a standard user fetches an entity, the server omits the `delete` link. If an administrator fetches the identical entity, the server attaches `"delete": { "href": "/api/v1/orders/501" }`.
- **Simplified Client Code:** Frontend clients eliminate complex, duplicated business rule engines:
  ```javascript
  // Client renders controls dynamically based on server-provided affordances:
  if (order._links.cancellation) {
      renderCancelButton(order._links.cancellation.href);
  }
  ```

---

### Hypermedia Format Standards: HAL and JSON:API

To standardize hypermedia structures, the IETF and industry established formal media types:

#### 1. HAL (Hypertext Application Language) — `application/hal+json`
The most widespread and lightweight standard in the Java/Spring ecosystem:
- **`_links`**: Map of link relations (`rel`) containing target URIs (`href`).
- **`_embedded`**: Embedded sub-resource collections, avoiding N+1 HTTP round-trips.

```json
{
  "_embedded": {
    "orders": [
      {
        "id": 501,
        "amount": 250.00,
        "_links": { "self": { "href": "/api/v1/orders/501" } }
      }
    ]
  },
  "_links": {
    "self": { "href": "/api/v1/orders?page=1" },
    "next": { "href": "/api/v1/orders?page=2" },
    "prev": { "href": "/api/v1/orders?page=0" }
  }
}
```

#### 2. JSON:API — `application/vnd.api+json`
A more rigid specification prescribing distinct root objects for `data`, `attributes`, `relationships`, and `links`.

### The Reverse Proxy Link Corruption Problem

In containerized cloud environments (Kubernetes, AWS ECS), Spring Boot applications run behind reverse proxies or API gateways (NGINX, Envoy, Traefik):
- When building links, Spring inspects the local servlet context and generates internal container IPs: `http://10.244.1.15:8080/api/v1/orders/501`.
- If returned to the browser, client navigation fails with network errors.

**The Production Fix:**
1. Configure reverse proxies to pass RFC 7239 headers:
   - `X-Forwarded-Host: api.example.com`
   - `X-Forwarded-Proto: https`
   - `X-Forwarded-Port: 443`
   - `X-Forwarded-Prefix: /api/v1`
2. Enable framework-level header resolution in Spring Boot `application.properties`:
   ```properties
   server.forward-headers-strategy=FRAMEWORK
   ```
   This registers Spring's `ForwardedHeaderFilter`, ensuring `WebMvcLinkBuilder` constructs public, HTTPS-compliant gateway URIs.

## 🔴 Senior Level

### Why the Industry Largely Abandoned HATEOAS

While intellectually elegant, Level 3 HATEOAS is implemented in less than 5% of commercial enterprise applications. Senior engineers must articulate the pragmatic trade-offs:

1. **Component-Driven UI Incompatibility:** Modern web and mobile frontends (React, Vue, iOS Swift, Android Jetpack Compose) rely on static, design-system-driven component trees (Figma). Interfaces cannot reorganize arbitrarily based on runtime hypermedia links.
2. **Egress Bandwidth Bloat:** For a single resource, links inflate payload size by 30–50%. For collections containing hundreds of items, payload sizes increase **by 2x to 3x** due to repeating URI strings across every array element.
3. **CPU & Garbage Collection Overhead:** Dynamically generating links on high-throughput paths using `WebMvcLinkBuilder` relies on Java Reflection to inspect controller classes and method metadata, consuming CPU cycles and generating garbage on high-RPS services.
4. **The OpenAPI / TypeScript Revolution:** Development teams strongly prefer compile-time typed SDKs generated from OpenAPI 3.1 YAML specs over runtime link parsing.

### Production Implementation with Spring HATEOAS

Spring Boot provides first-class support via `spring-boot-starter-hateoas` and `RepresentationModelAssembler`:

```java
package com.example.dto;

import com.example.controller.OrderController;
import com.example.entity.Order;
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.server.RepresentationModelAssembler;
import org.springframework.stereotype.Component;

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

@Component
public class OrderModelAssembler implements RepresentationModelAssembler<Order, EntityModel<OrderDto>> {

    @Override
    public EntityModel<OrderDto> toModel(Order order) {
        OrderDto dto = new OrderDto(order.getId(), order.getStatus(), order.getTotalAmount());

        // Canonical self link
        EntityModel<OrderDto> model = EntityModel.of(dto,
                linkTo(methodOn(OrderController.class).getOrderById(order.getId())).withSelfRel()
        );

        // State Machine: Dynamic link attachment based on entity lifecycle
        if ("AWAITING_PAYMENT".equals(order.getStatus())) {
            model.add(
                    linkTo(methodOn(OrderController.class).payOrder(order.getId())).withRel("payment"),
                    linkTo(methodOn(OrderController.class).cancelOrder(order.getId())).withRel("cancellation")
            );
        } else if ("PAID".equals(order.getStatus())) {
            model.add(
                    linkTo(methodOn(OrderController.class).getDeliveryStatus(order.getId())).withRel("delivery")
            );
        }

        return model;
    }
}
```

```java
package com.example.controller;

import com.example.dto.OrderDto;
import com.example.dto.OrderModelAssembler;
import com.example.entity.Order;
import com.example.service.OrderService;
import org.springframework.hateoas.EntityModel;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/orders")
public class OrderController {

    private final OrderService orderService;
    private final OrderModelAssembler assembler;

    public OrderController(OrderService orderService, OrderModelAssembler assembler) {
        this.orderService = orderService;
        this.assembler = assembler;
    }

    @GetMapping(value = "/{id}", produces = "application/hal+json")
    public ResponseEntity<EntityModel<OrderDto>> getOrderById(@PathVariable Long id) {
        Order order = orderService.findById(id);
        return ResponseEntity.ok(assembler.toModel(order));
    }

    @PostMapping("/{id}/payments")
    public ResponseEntity<Void> payOrder(@PathVariable Long id) {
        orderService.processPayment(id);
        return ResponseEntity.noContent().build();
    }

    @PostMapping("/{id}/cancellations")
    public ResponseEntity<Void> cancelOrder(@PathVariable Long id) {
        orderService.cancel(id);
        return ResponseEntity.noContent().build();
    }

    @GetMapping("/{id}/delivery")
    public ResponseEntity<String> getDeliveryStatus(@PathVariable Long id) {
        return ResponseEntity.ok("IN_TRANSIT");
    }
}
```

### HATEOAS Caching & the `Vary: Authorization` Header

If the server dynamically attaches links based on caller permissions (e.g., an administrator receives `rel="delete"`, but a standard user does not), the response **must never be cached publicly** without proper cache segregation:

```http
Cache-Control: private, max-age=300
Vary: Authorization
```

Without `Vary: Authorization`, a shared CDN edge cache or corporate proxy might serve an administrator's cached response (containing privileged action links) to an unauthorized user.

## 4 Tricky Questions

### 1. What is an Affordance in the context of HATEOAS?

**Answer:**
An Affordance is a hypermedia-delivered capability descriptor signaling to the client **what action can be performed directly from the entity's current state**.
- If a link relation (e.g., `rel="cancel"`) is present in `_links`, the client knows the operation is permissible under current business rules and security policies.
- If the resource transitions to an unalterable state or the user lacks clearance, the server withholds the link, preventing illegal state transitions before requests are dispatched.

---

### 2. What causes Spring HATEOAS links to output `http://localhost:8080` or internal pod IPs in production, and how is it fixed?

**Answer:**
This occurs when the service runs behind an API Gateway or reverse proxy (NGINX, AWS ALB) performing TLS termination or URL rewriting.
- `WebMvcLinkBuilder` inspects `HttpServletRequest`, which reflects the local container IP and port.
- **The Fix:** The reverse proxy must supply `X-Forwarded-Host`, `X-Forwarded-Proto`, and `X-Forwarded-Port`. In Spring Boot, configure:
  `server.forward-headers-strategy=FRAMEWORK`
  This enables `ForwardedHeaderFilter`, which wraps the request and forces link builders to construct canonical public gateway URLs.

---

### 3. Why does HATEOAS degrade throughput in highload distributed microservices?

**Answer:**
1. **Network Saturation:** Repeating hypermedia link blocks for each item in a collection multiplies response payload size by $2\times\text{--}3\times$, inflating network serialization latency and CDN egress billing.
2. **CPU & Memory Pressure:** Runtime link assembly via reflection (`WebMvcLinkBuilder`, `methodOn`) inspects controller method parameter types and annotations on every single invocation, imposing substantial GC allocation overhead at high RPS.

---

### 4. How must HATEOAS responses be cached when the returned links depend on user permissions?

**Answer:**
The server must attach **`Cache-Control: private`** to prevent intermediary proxies and CDNs from storing the payload in shared caches.
- Furthermore, the server must supply the **`Vary: Authorization`** header.
- This instructs client-side and edge caches that representations vary according to the caller's credentials, preventing privileged administrative action links from leaking to unprivileged users.

## 🎯 Interview Cheat Sheet

### 30-Second Elevator Pitch
> **HATEOAS (Richardson Maturity Model Level 3)** is the REST constraint where servers return hypermedia links (`_links`) alongside domain data, transforming the API into a self-describing **Finite State Machine**.
> 
> Clients navigate the API dynamically via link relations (`rel`) rather than hardcoding URIs. The standard representation format is **HAL (`application/hal+json`)**.
> 
> In production, HATEOAS is rarely adopted due to 30–200% payload bloat, CPU reflection costs, and the widespread industry preference for static compile-time typed OpenAPI contracts.

---

### Red Flags (What NOT to Say)
- ❌ *"An API cannot be called REST unless it implements HATEOAS."* (Richardson Level 2 is the universally accepted pragmatic standard for production REST APIs).
- ❌ *"HATEOAS optimizes network traffic and reduces payload size."* (It increases payload size significantly by adding link graphs).
- ❌ *"Mobile apps must use HATEOAS to render their UI."* (Mobile applications have rigid, pre-compiled UI layouts that cannot adapt to dynamic link graphs).
- ❌ *"HATEOAS links are constructed by manual string concatenation in controllers."* (Production applications use typed assemblers such as Spring's `RepresentationModelAssembler` and `WebMvcLinkBuilder`).
