# Что делает операция collect()

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
**`collect()`** — это ключевая терминальная операция Stream API, которая запускает выполнение всего конвейера обработки и упаковывает элементы потока в итоговую структуру данных (коллекцию `List`, `Set`, `Map`, строку или сводную статистику). 

Она реализует паттерн **мутабельной редукции (Mutable Reduction)**: вместо того чтобы создавать новый неизменяемый объект при обработке каждого элемента, `collect()` последовательно накапливает значения в единый изменяемый контейнер (например, `ArrayList`, `StringBuilder` или `HashMap`). После вызова `collect()` стрим считается потребленным и закрывается.

---

### Базовые примеры на Java 21

```java
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.stream.Collectors;

public class CollectBasicsDemo {

    record Item(String name, String category, double price) {}

    public static void main(String[] args) {
        List<Item> items = List.of(
            new Item("Laptop", "Electronics", 1200.0),
            new Item("Phone", "Electronics", 800.0),
            new Item("Book", "Stationery", 25.0)
        );

        // 1. Сборка в Set (устранение дубликатов)
        Set<String> categories = items.stream()
            .map(Item::category)
            .collect(Collectors.toSet());

        // 2. Объединение строк с разделителем и обрамлением
        String titles = items.stream()
            .map(Item::name)
            .collect(Collectors.joining(", ", "Items: [", "]"));
        System.out.println(titles); // Items: [Laptop, Phone, Book]

        // 3. Группировка (аналог SQL GROUP BY)
        Map<String, List<Item>> byCategory = items.stream()
            .collect(Collectors.groupingBy(Item::category));

        // 4. Современная сборка в неизменяемый список (Java 16+)
        List<String> names = items.stream()
            .map(Item::name)
            .toList(); // Альтернатива Collectors.toList()
    }
}
```

## 🟡 Middle Level

### Две формы вызова метода `collect()`

1. **С использованием готового `Collector`:**
   ```java
   <R, A> R collect(Collector<? super T, A, R> collector)
   ```
2. **Низкоуровневая трехкомпонентная форма (Three-argument overload):**
   ```java
   <R> R collect(Supplier<R> supplier, 
                 BiConsumer<R, ? super T> accumulator, 
                 BiConsumer<R, R> combiner)
   ```
   Пример ручной сборки в `StringBuilder`:
   ```java
   String result = list.stream().collect(
       StringBuilder::new,           // supplier: создаем контейнер
       StringBuilder::append,        // accumulator: добавляем элемент
       StringBuilder::append         // combiner: объединяем две ветки в parallelStream
   ).toString();
   ```

---

### Анатомия интерфейса `Collector<T, A, R>`
Интерфейс параметризован тремя типами:
- `T` — тип входящих элементов стрима.
- `A` — тип промежуточного аккумулятора (контейнера).
- `R` — итоговый тип результата.

```
                  ┌─── supplier(): () -> A
                  │    Создает новый пустой накопитель (напр. ArrayList::new)
                  │
                  ├─── accumulator(): (A, T) -> void
                  │    Добавляет входной элемент в накопитель (напр. List::add)
Collector<T,A,R> ─┤
                  ├─── combiner(): (A, A) -> A
                  │    Сливает два накопителя при параллельном вычислении
                  │
                  ├─── finisher(): A -> R
                  │    Финальное преобразование (напр. Collections::unmodifiableList)
                  │
                  └─── characteristics(): Set<Characteristics>
                       Флаги оптимизации (IDENTITY_FINISH, CONCURRENT, UNORDERED)
```

---

### Почему `collect()` эффективнее `reduce()` для коллекций?
- **Немутабельная редукция (`reduce`):** На каждом шаге конкатенирует данные в новый объект. Для списка это означает копирование всех ранее накопленных элементов:
  $$1 + 2 + 3 + \dots + N = O(N^2)$$
  Кроме того, это создает миллионы промежуточных массивов в куче (Heap), перегружая GC.
- **Мутабельная редукция (`collect`):** Модифицирует один и тот же существующий контейнер `ArrayList` вызовом `add()`. Сложность добавления амортизирована:
  $$O(N)$$

---

### Группировка данных (`groupingBy`) и вложенные коллекторы
Метод `Collectors.groupingBy` — это один из самых мощных инструментов в Java, позволяющий создавать многоуровневые агрегации:

```java
// Подсчет количества товаров в каждой категории
Map<String, Long> countByCategory = items.stream()
    .collect(Collectors.groupingBy(
        Item::category, 
        Collectors.counting() // Downstream коллектор
    ));

// Поиск самого дорогого товара в каждой категории
Map<String, Optional<Item>> mostExpensiveByCategory = items.stream()
    .collect(Collectors.groupingBy(
        Item::category,
        Collectors.maxBy(Comparator.comparingDouble(Item::price))
    ));
```

## 🔴 Senior Level

### Флаги оптимизации `Characteristics`
Конвейер использует характеристики коллектора для исключения лишних фаз обработки:

1. **`IDENTITY_FINISH`:**
   Указывает, что метод `finisher()` представляет собой тождественную функцию `Function.identity()`. JVM пропускает финальный шаг и выполняет прямой каст аккумулятора к возвращаемому типу: `(R) accumulator`.
2. **`CONCURRENT`:**
   Указывает, что накопитель является **потокобезопасным** (например, `ConcurrentHashMap` или `ConcurrentLinkedQueue`). 
   - В параллельных стримах (`parallelStream`) JVM **НЕ создает отдельные аккумуляторы для каждого потока ядра и НЕ вызывает `combiner()`**.
   - Все параллельные потоки пишут напрямую в **один общий разделяемый контейнер**, что дает колоссальный прирост производительности при сборе в многопоточных средах.
3. **`UNORDERED`:**
   Указывает, что операция сбора не сохраняет порядок элементов источника (ускоряет параллельную обработку).

### Подводные камни `Collectors.toMap()`
Метод `Collectors.toMap` таит в себе две критические уязвимости:

#### 1. Коллизии ключей (Duplicate Keys)
```java
// ❌ ПАДЕНИЕ В RUNTIME:
// Если в списке окажутся два пользователя с одинаковым email:
// java.lang.IllegalStateException: Duplicate key user@test.com
Map<String, User> map = users.stream()
    .collect(Collectors.toMap(User::email, u -> u));

// ✅ ОБЯЗАТЕЛЬНО: всегда передавать функцию разрешения конфликтов (Merge Function)
Map<String, User> safeMap = users.stream()
    .collect(Collectors.toMap(
        User::email, 
        u -> u, 
        (existing, replacement) -> existing // Сохраняем первый или берем новый
    ));
```

#### 2. Опасность Null-значений
Стандартный коллектор `Collectors.toMap()` внутри использует `Map.merge()`. Метод `Map.merge()` по спецификации JDK **выбрасывает `NullPointerException`, если новое или существующее значение равно `null`**!
Если функция маппинга значения может вернуть `null`, `Collectors.toMap()` упадет даже при отсутствии коллизий ключей.

### `Stream.toList()` (Java 16+) vs `Collectors.toList()`
В современном коде Java 16+ рекомендуется использовать встроенный терминальный метод `stream.toList()`:

| Критерий | `stream.toList()` (Java 16+) | `stream.collect(Collectors.toList())` |
| :--- | :--- | :--- |
| **Изменяемость** | **Неизменяемый (Unmodifiable):** вызов `add()` бросает `UnsupportedOperationException` | **Изменяемый:** возвращает стандартный `ArrayList` |
| **Память и аллокации** | Не создает объект `Collector`, использует прямой компактный массив | Аллоцирует `Collector` и обертки конвейера |
| **Допустимость null** | Полностью поддерживает `null` элементы | Полностью поддерживает `null` элементы |
| **Синтаксис** | Лаконичный: `.toList()` | Громоздкий: `.collect(Collectors.toList())` |

## 🎯 Шпаргалка для интервью

### Вопросы для быстрой проверки
1. **Каковы 4 основные функции интерфейса `Collector<T, A, R>`?**
   *Ответ:* `supplier()` (создает пустой контейнер-накопитель), `accumulator()` (добавляет элемент в контейнер), `combiner()` (сливает два контейнера при параллельной обработке), `finisher()` (преобразует накопитель в итоговый результат).
2. **В чем разница между `Stream.toList()` (Java 16+) и `Collectors.toList()`?**
   *Ответ:* `stream.toList()` возвращает неизменяемый (unmodifiable) компактный список, работает быстрее и не создает вспомогательных объектов коллектора. `Collectors.toList()` возвращает стандартный изменяемый `ArrayList`.
3. **Что произойдет при вызове `Collectors.toMap()` с дублирующимися ключами, если не передана merge-функция?**
   *Ответ:* Будет выброшено исключение `IllegalStateException: Duplicate key ...`. Для предотвращения сбоя необходимо использовать трехпараметрическую версию `toMap(keyMapper, valueMapper, mergeFunction)`.
4. **Что дает характеристика `Characteristics.CONCURRENT` в параллельном стриме?**
   *Ответ:* Она указывает, что контейнер аккумулятора потокобезопасен. Виртуальная машина не делит контейнеры по потокам и не вызывает `combiner()`, а позволяет всем потокам пула параллельно писать в один общий экземпляр (например, `ConcurrentHashMap`).

### Типичные ошибки и Red Flags
- ❌ **Утверждение: "`reduce()` так же хорош для сбора элементов в `List`, как и `collect()`":** Приводит к алгоритмической катастрофе $O(N^2)$ и копированию коллекций в памяти.
- ❌ **Использование `Collectors.toMap()` без merge-функции в продакшене:** Бомба замедленного действия при получении неожиданных дубликатов из базы или API.
- ❌ **Попытка вызвать `collect()` на стриме повторно:** Стрим закрывается навсегда после первого терминального вызова (`IllegalStateException`).
- ❌ **Использование `collect(toList()).size()` вместо `.count()`:** Бессмысленная аллокация списка в памяти ради получения его длины.
