# What is structured concurrency

---

## 🟢 Junior Level

### Short Interview Answer (30 Seconds)
**Structured Concurrency** is a programming paradigm (introduced in Java 21 under **JEP 453** as a Preview API) that treats multiple concurrent subtasks executing in separate threads as a **single, indivisible unit of work** with strictly defined lexical lifecycles.

In classic multi-threading (`ExecutorService`, `Thread.start()`), concurrency is unstructured (fire-and-forget): a parent thread can exit, crash, or return while leaving orphaned background threads running indefinitely (**Thread Leaks / Orphan Tasks**). Structured Concurrency eliminates this flaw through a strict contractual invariant: **"The lifecycle of child threads is strictly bounded by the syntactic block that spawned them."** If any subtask fails, all siblings are automatically cancelled, and the parent scope is guaranteed to block until all child tasks have completed before exiting the scope.

---

### Analogy: Eradicating `goto` from Concurrency

In 1968, Edsger W. Dijkstra published his famous manifesto *“Go To Statement Considered Harmful”*, demonstrating that arbitrary code jumps made program behavior incomprehensible. Structured programming replaced `goto` with `if`, `while`, and function calls: execution enters a block and is guaranteed to exit symmetrically.

Spawning an asynchronous task via `executor.submit()` is the modern concurrent equivalent of `goto`: execution splits into a background thread with no lexical guarantee of when or if it will ever rejoin the calling context.  
**Structured Concurrency transforms multithreading into structured control flow:** execution branches (**fork**) and is guaranteed to converge (**join**) within a single `try-with-resources` block.

---

### Comparison Table: Unstructured vs. Structured Concurrency

| Characteristic | Classic Approach (`ExecutorService`) | Structured Concurrency (`StructuredTaskScope`) |
|---|---|---|
| **Task Relationship** | Disconnected threads unaware of each other | Strict hierarchy: Parent $\to$ Child subtasks |
| **Thread Leaks** | Common (background tasks continue after parent failure) | **Physically impossible** (scope cannot close while children run) |
| **Failure Response** | Manual iteration and `future.cancel()` calls | **Automatic cascading cancellation** (Short-circuiting) |
| **Thread Dumps** | Flat list of thousands of anonymous worker threads | **Hierarchical call tree** (Parent/Child structure) |
| **Context Propagation** | `InheritableThreadLocal` (costly allocations, leak risk) | `ScopedValue` (immutable, zero-allocation sharing) |
| **Virtual Threads Synergy** | Requires manual pool management | Designed explicitly for millions of virtual threads |

### Java 21 Basic Example

```java
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.StructuredTaskScope.Subtask;

public class StructuredConcurrencyBasicsDemo {

    public record UserProfile(String user, String orders) {}

    // Parallel aggregation of user profile and orders
    public UserProfile fetchUserProfile(long userId) throws Exception {
        // Create scope with fail-fast policy: cancel all subtasks if any fails
        try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
            
            // Fork subtasks (automatically executed on Virtual Threads)
            Subtask<String> userTask = scope.fork(() -> queryUserService(userId));
            Subtask<String> ordersTask = scope.fork(() -> queryOrderService(userId));

            // Wait until both subtasks complete (or one fails)
            scope.join();
            
            // If either task failed, rethrow exception and cancel remaining peers
            scope.throwIfFailed(ex -> new RuntimeException("Profile aggregation failed", ex));

            // Results are guaranteed complete, safe to retrieve without blocking
            return new UserProfile(userTask.get(), ordersTask.get());
        } // try-with-resources guarantees: all spawned threads are terminated before exiting!
    }

    private String queryUserService(long id) throws Exception {
        Thread.sleep(50); // Simulate I/O latency
        return "UserData_" + id;
    }

    private String queryOrderService(long id) throws Exception {
        Thread.sleep(80); // Simulate I/O latency
        return "OrdersList_" + id;
    }
}
```

## 🟡 Middle Level

### Shutdown Policies

`StructuredTaskScope` provides two standard out-of-the-box lifecycle management strategies:

#### 1. `ShutdownOnFailure` (All-or-Nothing / Composite Aggregation)
Used when a business result requires **all** concurrent subtasks to succeed (e.g., API gateway aggregating user details, order history, and payment status).  
- If any subtask throws an exception:
  1. The scope transitions to the `shutdown` state;
  2. All remaining active sibling subtasks immediately receive a `Thread.interrupt()` signal;
  3. `scope.throwIfFailed()` rethrows the root exception into the parent thread.

#### 2. `ShutdownOnSuccess<T>` (First-Success / Speculative Race)
Used when a result from **any single successful** subtask is sufficient (e.g., querying redundant multi-region DNS mirrors or distributed cache nodes).

```java
import java.util.concurrent.StructuredTaskScope;

public class FastMirrorService {

    // Race three mirrors: grab the fastest successful response and cancel the rest
    public String getFastestContent(String url) throws Exception {
        try (var scope = new StructuredTaskScope.ShutdownOnSuccess<String>()) {
            scope.fork(() -> downloadFromHost("mirror-us.cdn.org", url));
            scope.fork(() -> downloadFromHost("mirror-eu.cdn.org", url));
            scope.fork(() -> downloadFromHost("mirror-asia.cdn.org", url));

            scope.join(); // Wait for the first subtask to succeed

            // Returns the result of the winning subtask;
            // The other two subtasks are automatically interrupted!
            return scope.result();
        }
    }

    private String downloadFromHost(String host, String url) throws Exception {
        // Simulate network download
        return "Data from " + host;
    }
}
```

---

### Cooperative Cancellation Mechanism

Cancellation in Structured Concurrency relies on Java's standard interrupt mechanism—**`Thread.interrupt()`**.

When a scope policy initiates shutdown via `shutdown()`:
1. All running virtual threads receive the thread interruption flag;
2. Standard blocking calls (`Socket.read()`, `Thread.sleep()`, `ReentrantLock.lockInterruptibly()`) wake up immediately and throw `InterruptedException`;
3. Long-running CPU-bound loops must periodically check for interruption:
   ```java
   while (!Thread.currentThread().isInterrupted()) {
       // Perform chunk of computation
   }
   ```
4. `scope.join()` blocks until all interrupted threads complete their `finally` cleanup blocks and terminate.

---

### Context Propagation via `ScopedValue`

Unlike `InheritableThreadLocal`, which performs a costly deep-copy of the parent's entire thread-local map on every thread creation, `ScopedValue` shares immutable context with child virtual threads with zero allocation overhead:

```java
public class SecurityContextHandler {
    public static final ScopedValue<SecurityPrincipal> PRINCIPAL = ScopedValue.newInstance();

    public void handleUserRequest(SecurityPrincipal user) throws Exception {
        ScopedValue.where(PRINCIPAL, user).run(() -> {
            try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
                // Subtasks safely inherit PRINCIPAL without copying or memory leak risk:
                scope.fork(() -> auditLog(PRINCIPAL.get()));
                scope.fork(() -> executeOperation(PRINCIPAL.get()));
                scope.join();
            }
        });
    }

    private void auditLog(SecurityPrincipal principal) {}
    private void executeOperation(SecurityPrincipal principal) {}
}
```

## 🔴 Senior Level

### Under the Hood: Invariants and State Machine

At the JVM runtime level, `StructuredTaskScope` enforces strict state transitions to eliminate concurrency bugs by design:

```
Scope Lifecycle States:
[ OPEN ] ── fork() ──> [ FORKING ] ── join() ──> [ JOINED ] ── close() ──> [ CLOSED ]
```

1. **Calling `subtask.get()` Before `join()`:**  
   Calling `subtask.get()` prior to invoking `scope.join()` immediately throws **`IllegalStateException`** because the subtask has not yet reached a guaranteed terminal state.
2. **Mandatory Scope Closure (`close()`):**  
   If the parent thread attempts to exit the block prematurely (e.g., via an unhandled exception or early `return`), `try-with-resources` invokes `scope.close()`. The `close()` method invokes an implicit `join()` that blocks the parent until all running child virtual threads have terminated. No child thread can ever leak past the enclosing block.

---

### Hierarchical Observability (JSON Thread Dumps)

The principal operational challenge with legacy thread pools is context loss: when capturing a `jstack` dump, hundreds of worker threads appear identical, making it impossible to correlate which thread belongs to which incoming HTTP transaction.

Structured Concurrency integrates directly into Java's diagnostic tools, exposing a clear **Hierarchical Task Tree**:
```bash
# Capture structured thread dump in JSON format:
jcmd <PID> Thread.dump_to_file -format=json thread_dump.json
```

The dump reveals parent-child causality:
```json
{
  "thread": "VirtualThread[#45,tomcat-handler-1]",
  "scope": "StructuredTaskScope$ShutdownOnFailure[#12]",
  "children": [
    { "thread": "VirtualThread[#46,fork-queryUserService]" },
    { "thread": "VirtualThread[#47,fork-queryOrderService]" }
  ]
}
```
Site reliability engineers can immediately determine: *"Thread #47 is stuck waiting on a database query, blocking parent Tomcat request handler #45"*.

### Implementing a Custom Policy: Quorum Pattern

A Senior Engineer can override the `handleComplete(Subtask<T>)` hook to implement specialized consensus logic, such as a **Quorum Scope** (requiring 2 out of 3 node confirmations):

```java
import java.util.Collection;
import java.util.Collections;
import java.util.concurrent.ConcurrentLinkedQueue;
import java.util.concurrent.StructuredTaskScope;

public class QuorumScope<T> extends StructuredTaskScope<T> {
    private final int threshold;
    private final Collection<T> successes = new ConcurrentLinkedQueue<>();
    private final Collection<Throwable> failures = new ConcurrentLinkedQueue<>();

    public QuorumScope(int threshold) {
        this.threshold = threshold;
    }

    @Override
    protected void handleComplete(Subtask<? extends T> subtask) {
        if (subtask.state() == Subtask.State.SUCCESS) {
            successes.add(subtask.get());
            if (successes.size() >= threshold) {
                // Quorum reached: cancel remaining slower replicas!
                this.shutdown();
            }
        } else if (subtask.state() == Subtask.State.FAILED) {
            failures.add(subtask.exception());
        }
    }

    public Collection<T> getQuorumResults() {
        super.ensureOwnerAndJoined();
        if (successes.size() < threshold) {
            throw new RuntimeException("Quorum not reached. Failures encountered: " + failures);
        }
        return Collections.unmodifiableCollection(successes);
    }
}
```

## 🎯 Interview Cheat Sheet

### 1. 30-Second Elevator Pitch
**Structured Concurrency (Java 21, JEP 453)** structures concurrent subtasks into unified lexical units of work within `try-with-resources`, just as `if`/`while` blocks structure control flow. It eliminates thread leaks and orphaned tasks by ensuring child threads cannot outlive their enclosing scope. It provides automatic fail-fast cancellation (`ShutdownOnFailure`) or first-success short-circuiting (`ShutdownOnSuccess`), seamless context inheritance via `ScopedValue`, and hierarchical visibility in thread dumps (`jcmd`).

### 2. 4 Tricky Questions with Deep Answers

#### Question 1: What is the conceptual parallel between Dijkstra's elimination of `goto` in 1968 and the introduction of Structured Concurrency?
**Answer:**
The `goto` statement allowed arbitrary jumps across memory addresses, destroying mental models of program flow and making static reasoning impossible. Classic asynchronous execution (`new Thread().start()` or `executor.submit()`) is the concurrent equivalent of `goto`: execution forks into an untracked background thread that escapes the call stack, with no syntactic guarantee of return. Structured Concurrency restores lexical discipline: concurrent execution forks and rejoins strictly within the boundaries of a single `try-with-resources` block.

#### Question 2: What happens if code inside a `StructuredTaskScope` block calls `subtask.get()` without calling `scope.join()` first, or forgets to invoke `join()` before exiting?
**Answer:**
1. If `subtask.get()` is invoked prior to `scope.join()`, the API immediately throws **`IllegalStateException: Subtask not completed`**. Accessing results is prohibited until the parent explicitly joins the task scope.
2. If code attempts to exit the `try-with-resources` block without calling `join()`, the `scope.close()` method automatically blocks the current thread and executes an implicit join, awaiting the completion of all active child threads. It is impossible to leak running threads beyond the scope.

#### Question 3: How does `StructuredTaskScope` respond if the parent thread is interrupted while waiting on `scope.join()`?
**Answer:**
If the parent thread blocked on `scope.join()` receives an external interruption (`Thread.currentThread().interrupt()`), `join()` catches the signal, triggers `scope.shutdown()`, and broadcasts `Thread.interrupt()` to **all** active child subtasks spawned within the scope. `join()` then throws `InterruptedException`. This ensures that when an outer HTTP request or database transaction is cancelled, all underlying child operations are terminated immediately rather than burning CPU and I/O capacity in vain.

#### Question 4: Why is context propagation with `ScopedValue` in Structured Concurrency superior to `InheritableThreadLocal`?
**Answer:**
When using `InheritableThreadLocal`, every child thread allocates a full copy of the parent thread's internal map in the heap. Across thousands or millions of virtual threads, this produces catastrophic memory churn and risks memory leaks if child threads are pooled or uncleaned. In contrast, `ScopedValue` is immutable and lexically scoped: child subtasks in `StructuredTaskScope` directly read the parent's memory reference without copying or heap allocations, and the context is automatically reclaimed when the lexical scope exits.

### 3. Common Pitfalls and Red Flags

❌ **"Using `StructuredTaskScope` for background workers, queue consumers, or daemons."**  
*Correction:* Structured Concurrency is designed strictly for bounded fork-join tasks with defined start and end points. Long-lived background event loops (Kafka consumers, batch workers) should continue using classic `ExecutorService`.

❌ **"Ignoring thread interruption flags inside CPU-intensive subtasks."**  
*Correction:* If a subtask executes a tight CPU loop without checking `Thread.currentThread().isInterrupted()`, cascading cancellation cannot stop the thread, causing `scope.close()` to block indefinitely.

❌ **"Assuming Structured Concurrency is final, stable LTS API in Java 21."**  
*Correction:* In Java 21, `StructuredTaskScope` is a Preview API (`--enable-preview`), with ongoing refinements in Java 22, 23, and beyond.
