# Что делает операция reduce()

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
**`reduce()` (Редукция / Свёртка)** — это терминальная операция Stream API, которая последовательно объединяет все элементы потока в **одно результирующее значение** с помощью заданной функции-аккумулятора (например, нахождение суммы, произведения, минимума или конкатенации).

Операция `reduce()` реализует паттерн **иммутабельной редукции**: на каждом шаге она возвращает новое значение, не мутируя исходные объекты. Существуют три перегрузки метода:
1. `reduce(BinaryOperator<T> accumulator)` — возвращает `Optional<T>` (так как поток может быть пустым).
2. `reduce(T identity, BinaryOperator<T> accumulator)` — возвращает `T` (при пустом потоке возвращается начальное значение `identity`).
3. `reduce(U identity, BiFunction<U, ? super T, U> accumulator, BinaryOperator<U> combiner)` — позволяет вернуть тип `U`, отличный от типа элементов потока `T`.

---

### Примеры использования на Java 21

```java
import java.util.List;
import java.util.Optional;

public class ReduceBasicsDemo {

    public static void main(String[] args) {
        List<Integer> numbers = List.of(2, 3, 4, 5);

        // 1. Без identity: возвращает Optional
        Optional<Integer> productOpt = numbers.stream()
            .reduce((a, b) -> a * b);
        System.out.println("Произведение: " + productOpt.orElse(0)); // 120

        // 2. С начальным значением (identity = 0 для суммы): возвращает примитив/значение
        int sum = numbers.stream()
            .reduce(0, Integer::sum);
        System.out.println("Сумма: " + sum); // 14

        // 3. Поиск максимального элемента
        int max = numbers.stream()
            .reduce(Integer.MIN_VALUE, Integer::max);
        System.out.println("Максимум: " + max); // 5

        // 4. Поведение на пустом стриме
        List<Integer> empty = List.of();
        int emptyResult = empty.stream().reduce(42, Integer::sum);
        System.out.println("Пустой стрим с identity: " + emptyResult); // 42
    }
}
```

## 🟡 Middle Level

### Математический контракт моноида: Identity и Ассоциативность

Корректность работы `reduce()` (особенно при переходе на `parallelStream()`) базируется на концепции **моноида** из абстрактной алгебры и требует строгого соблюдения двух математических свойств:

#### 1. Нейтральный элемент (`identity`)
Функция аккумулятора должна возвращать исходный элемент при передаче `identity`:
$$\text{accumulator}(\text{identity}, v) = v$$
- Для сложения: $\text{identity} = 0$ ($0 + x = x$).
- Для умножения: $\text{identity} = 1$ ($1 \times x = x$).
- Для поиска максимума: $\text{identity} = -\infty$ (`Integer.MIN_VALUE`).

> ❌ **Ошибка:** Если для суммирования задать `identity = 100`, то в последовательном стриме результат увеличится на 100, а в параллельном стриме из 4 потоков каждый поток прибавит 100 к своему чанку, и итоговая сумма увеличится на $4 \times 100 = 400$!

#### 2. Ассоциативность (Associativity)
Порядок группировки операций не должен влиять на результат:
$$(a \circ b) \circ c = a \circ (b \circ c)$$
Это позволяет потокам `ForkJoinPool` произвольно дробить поток на ветви и объединять частичные результаты в любом порядке:

```
Последовательно:       ((1 + 2) + 3) + 4 = 10
Параллельно:          (1 + 2) + (3 + 4) = 3 + 7 = 10
```

> ❌ **Неассоциативные операции:** Вычитание (`a - b`) или деление не обладают ассоциативностью: $(10 - 2) - 3 = 5$, но $10 - (2 - 3) = 11$. Вызов `.parallelStream().reduce((a, b) -> a - b)` вернет недетерминированный хаотичный результат!

## 🔴 Senior Level

### Третья сигнатура `reduce()`: Зачем нужен `Combiner`

```java
<U> U reduce(U identity, 
             BiFunction<U, ? super T, U> accumulator, 
             BinaryOperator<U> combiner);
```

В этой сигнатуре тип аккумулятора `U` отличается от типа элементов потока `T`.

```java
List<String> words = List.of("Java", "Stream", "API");

int totalLength = words.parallelStream()
    .reduce(
        0,                                 // identity: U (Integer)
        (acc, str) -> acc + str.length(),  // accumulator: (U, T) -> U
        Integer::sum                       // combiner: (U, U) -> U
    );
```

#### Механика исполнения:
1. **В последовательном стриме:** `combiner` **никогда не вызывается**. Стрим идет последовательно, вызывая `accumulator.apply(acc, element)` на каждом шаге.
2. **В параллельном стриме:**
   - Каждый рабочий поток `ForkJoinWorkerThread` независимо накапливает частичную сумму элементов своего чанка в тип `U` с помощью `accumulator`.
   - На этапе завершения дочерних задач `ForkJoinPool` вызывает `combiner.apply(u1, u2)` для попарного слияния промежуточных результатов типа `U` в дереве свертки.

### Антипаттерн: Мутабельная редукция через `reduce()`

Частая ошибка — попытка собрать коллекцию через `reduce()`:

```java
// ❌ АНТИПАТТЕРН: $O(N^2)$ аллокаций и поломка параллелизма
List<String> bad = stream.reduce(
    new ArrayList<>(),
    (list, item) -> {
        list.add(item); // Мутация общего списка или постоянное копирование!
        return list;
    },
    (left, right) -> {
        left.addAll(right);
        return left;
    }
);
```

**Почему это недопустимо:**
1. При параллельном выполнении разные потоки одновременно мутируют один и тот же переданный объект `identity = new ArrayList<>()`, порождая гонки данных.
2. Если создавать новый список на каждом шаге, сложность алгоритма вырастет с $O(N)$ до $O(N^2)$ из-за непрерывного копирования массивов.
3. Для накопления в изменяемые структуры данных существует специализированная операция **мутабельной редукции** — **`collect()`**.

## 🎯 Шпаргалка для интервью

### 30-секундный ответ
> «`reduce()` — это терминальная операция иммутабельной свёртки элементов стрима в одно итоговое значение. Для корректной работы аккумулятора требуется соблюдение свойств моноида: наличие нейтрального элемента `identity` и строгая ассоциативность функции (порядок объединения скобок не важен). При неассоциативных операциях (например, вычитании) параллельный стрим возвращает неверный результат. Третья перегрузка `reduce` с `combiner` применяется при смене типа данных, при этом `combiner` вызывается исключительно в параллельном режиме для слияния частичных результатов.»

---

### Сводная таблица трех перегрузок `reduce`

| Сигнатура | Возвращаемый тип | Поведение на пустом стриме | Назначение combiner |
|---|---|---|---|
| `reduce(accumulator)` | `Optional<T>` | `Optional.empty()` | Не требуется (тип $T$) |
| `reduce(identity, accumulator)` | `T` | Возвращает `identity` | Не требуется (тип $T$) |
| `reduce(identity, accumulator, combiner)` | `U` | Возвращает `identity` | **Слияние результатов $U$ в `parallelStream`** |

### Топ-4 каверзных вопроса на интервью

#### 1. Почему `reduce()` со сбором в `ArrayList` является антипаттерном со сложностью $O(N^2)$?
- `reduce()` предназначен для неизменяемых типов данных (числа, строки, объекты-значения). Если создавать новый список на каждом элементе, на каждом шаге $i$ копируется $i$ элементов, что дает сумму арифметической прогрессии $\sum_{i=1}^N i = O(N^2)$. Если же мутировать переданный список, в параллельном режиме произойдет гонка данных за один экземпляр `identity`. Для изменяемых коллекций нужно использовать `collect()`.

#### 2. Что произойдет, если в качестве `identity` передать ненейтральный элемент (например, 10 при суммировании) в `parallelStream`?
- Результат будет фатально завышен. В параллельном стриме данные разбиваются на $K$ подзадач по числу задействованных воркеров `ForkJoinPool`. Каждый воркер начнет суммирование со значения `identity = 10`. При слиянии результатов ветвей число 10 будет учтено не один раз, а $K$ раз.

#### 3. Почему параметр `combiner` вообще не вызывается в последовательном стриме?
- В однопоточном исполнении нет параллельных ветвей вычислений. Существует единственный поток и один аккумулятор типа `U`, который последовательно обновляется через `accumulator.apply(u, t)`. Сливать нечего, поэтому рантайм `ReferencePipeline` оптимизирует код и полностью игнорирует `combiner`.

#### 4. Как математические свойства моноида гарантируют корректность `reduce` в параллельных стримах?
- Моноид требует замкнутости, нейтрального элемента и ассоциативности. Ассоциативность гарантирует, что дерево декомпозиции `ForkJoinTask` может делить массив в любых точках и объединять результаты в произвольном порядке узлов дерева: $(A + B) + (C + D) = A + (B + (C + D))$. Это фундамент алгоритма «разделяй и властвуй».

### Типичные ошибки и Red Flags
- 🚩 Использование неассоциативных операций (вычитание, деление) в `reduce()`.
- 🚩 Использование `reduce()` для накопления элементов в `List`, `Set` или `StringBuilder` вместо `collect()`.
- 🚩 Задание ненейтрального `identity`, приводящее к умножению начального смещения в параллельных потоках.
- 🚩 Забывание о примитивных стримах (`mapToInt().sum()`), приводящее к миллионам аллокаций автобоксинга в `reduce(0, Integer::sum)`.
