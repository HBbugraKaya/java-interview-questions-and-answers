# Як працює коротке замикання (short-circuiting) в Stream

---

## 🟢 Junior Level

### Коротка відповідь для співбесіди (30 секунд)
**Коротке замикання (Short-Circuiting)** у Stream API — це механізм дострокової зупинки обробки елементів, щойно результат роботи конвеєра стає однозначно визначеним.

Це прямий аналог логічних операторів `&&` і `||` або ключового слова `break` у циклах:
- **Проміжні операції короткого замикання:** `limit(n)`, `takeWhile(predicate)` (Java 9+). Вони обмежують нескінченний або довгий потік даних.
- **Термінальні операції короткого замикання:** `findFirst()`, `findAny()`, `anyMatch()`, `allMatch()`, `noneMatch()`. Вони повертають результат одразу, щойно умова виконана (або спростована), не скануючи залишкові елементи.

---

### Приклади роботи на Java 21

```java
import java.util.List;

public class ShortCircuitingDemo {

    public static void main(String[] args) {
        List<String> names = List.of("Іван", "Петро", "Анна", "Сергій", "Дарія");

        // 1. anyMatch: припинить перевірку одразу після "Анна"
        boolean hasAnna = names.stream()
            .peek(name -> System.out.println("Перевіряємо: " + name))
            .anyMatch("Анна"::equals);

        System.out.println("Знайдено Анну: " + hasAnna);

        // 2. limit: візьме лише перші 2 елементи
        List<String> firstTwo = names.stream()
            .limit(2)
            .toList();
        System.out.println("Перші два: " + firstTwo); // [Іван, Петро]
    }
}
```

**Виведення в консоль:**
```
Перевіряємо: Іван
Перевіряємо: Петро
Перевіряємо: Анна
Знайдено Анну: true
Перші два: [Іван, Петро]
```
Елементи «Сергій» та «Дарія» навіть не зчитувалися з джерела.

## 🟡 Middle Level

### Класифікація операцій Short-Circuiting

| Операція | Тип | Умова дострокового переривання конвеєра |
|---|---|---|
| **`limit(n)`** | Intermediate | Оброблено рівно $n$ елементів |
| **`takeWhile(predicate)`** (Java 9+) | Intermediate | Зустрінуто перший елемент, для якого предикат повернув `false` |
| **`findFirst()` / `findAny()`** | Terminal | Знайдено хоча б один відповідний елемент |
| **`anyMatch(predicate)`** | Terminal | Знайдено хоча б один елемент зі значенням `true` |
| **`allMatch(predicate)`** | Terminal | Знайдено хоча б один елемент зі значенням `false` |
| **`noneMatch(predicate)`** | Terminal | Знайдено хоча б один елемент зі значенням `true` |

---

### Внутрішній протокол: `Sink.cancellationRequested()`

Управління достроковою зупинкою конвеєра реалізовано на рівні базового інтерфейсу `java.util.stream.Sink`:

```java
public interface Sink<T> extends Consumer<T> {
    default void begin(long size) {}
    default void end() {}
    
    // Перевірка запиту на скасування обчислень:
    default boolean cancellationRequested() {
        return false;
    }
}
```

#### Механізм передачі сигналу про скасування:
1. Термінальна операція (наприклад, `anyMatch`) при знаходженні збігу виставляє внутрішній прапорець `stop = true`. Метод `cancellationRequested()` починає повертати `true`.
2. Проміжний вузол конвеєра (`filter`, `map`) перевіряє `downstream.cancellationRequested()`.
3. `Spliterator` опитує downstream-`Sink`: метод `spliterator.tryAdvance(action)` припиняє вилучення елементів з джерела, щойно `sink.cancellationRequested()` повертає `true`.

## 🔴 Senior Level

### Механіка в `parallelStream()`: `FindTask` та скасування підзадач

У багатопотоковому режимі (`ForkJoinPool`) поведінка операцій пошуку суттєво відрізняється:

```
ForkJoinPool Parallel Processing:
Worker 1 [0..25]:    Шукає...
Worker 2 [26..50]:   Знайшов збіг! ──► findAny(): миттєво скасовує воркерів 1, 3, 4!
Worker 3 [51..75]:   Шукає...          findFirst(): ЗОБОВ'ЯЗАНИЙ чекати Worker 1 (лівий чанк)!
Worker 4 [76..100]:  Шукає...
```

1. **`findAny()`:**
   - Використовує спеціалізовану задачу `FindTask`.
   - Щойно будь-який потік знаходить збіг, він викликає атомарний метод `task.cancelLaterNodes()`, скидаючи стан гілок у дереві `CountedCompleter` та негайно повертаючи результат.
2. **`findFirst()`:**
   - Зобов'язаний гарантувати збереження вихідного порядку обходу (**Encounter Order**).
   - Якщо збіг знайшов потік 2, він не має права повернути результат, доки потік 1 (який обробляє лівий діапазон) не завершить роботу й не підтвердить, що в лівій половині збігів не було. Тому `findFirst()` у паралельних стрімах працює суттєво повільніше за `findAny()`.

### Нескінченні стріми (Infinite Streams) та пастка зависання

Коротке замикання робить можливою обробку нескінченних стрімів:

```java
import java.util.List;
import java.util.stream.Stream;

public class InfiniteStreamSafetyDemo {

    public static void main(String[] args) {
        // ✅ БЕЗПЕЧНО: limit() перериває нескінченну генерацію
        List<Integer> firstTenPrimes = Stream.iterate(2, n -> n + 1)
            .filter(InfiniteStreamSafetyDemo::isPrime)
            .limit(5)
            .toList();

        System.out.println("Перші 5 простих чисел: " + firstTenPrimes);
    }

    private static boolean isPrime(int n) {
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) return false;
        }
        return true;
    }
}
```

> ⚠️ **Критична помилка (Infinite Hang):** Якщо предикат ніколи не виконається (наприклад, `stream.iterate(1, n -> n + 1).filter(n -> n < 0).findFirst()`), стрім перетвориться на **вічний цикл**, утилізуючи 100% ядра CPU в марних спробах знайти потрібний елемент.

---

### Java 9+: `takeWhile()` проти `filter().limit()`

У Java 9 з'явився метод `takeWhile(Predicate)`:
- `filter(p).limit(n)` змушений перевіряти предикат для всіх елементів, поки не збере $n$ штук, або до кінця стріму.
- `takeWhile(p)` зупиняє конвеєр **при першій же зустрічі елемента, що не задовольняє предикат**.
- На відсортованих даних `takeWhile()` відпрацьовує за $O(K)$, де $K$ — кількість відповідних елементів, тоді як `filter()` вимагає $O(N)$ повного сканування всього масиву.

## 🎯 Шпаргалка для інтерв'ю

### 30-секундна відповідь
> «Short-Circuiting — механізм дострокового переривання конвеєра, щойно відповідь стає однозначно відомою. До проміжних операцій належать `limit()` та `takeWhile()`, до термінальних — `findFirst()`, `findAny()`, `anyMatch()`, `allMatch()`, `noneMatch()`. Всередині конвеєра скасування передається через метод `Sink.cancellationRequested()`, який зупиняє `Spliterator.tryAdvance()`. У паралельних стрімах `findAny()` значно швидший за `findFirst()`, оскільки не потребує очікування результатів із попередніх за порядком чанків даних.»

---

### Зведена таблиця переривання операцій

| Операція | Умова переривання (Return Fast) | Складність у найгіршому випадку |
|---|---|---|
| `anyMatch(p)` | Перший елемент, де `p.test(x) == true` | $O(N)$ (якщо не знайдено) |
| `allMatch(p)` | Перший елемент, де `p.test(x) == false` | $O(N)$ (якщо всі true) |
| `noneMatch(p)` | Перший елемент, де `p.test(x) == true` | $O(N)$ (якщо всі false) |
| `findFirst()` | Перший за порядком відповідний елемент | $O(N)$ |
| `findAny()` | Будь-який перший знайдений потоком елемент | $O(N)$ (але в parallel швидше) |
| `takeWhile(p)` | Перший елемент, де `p.test(x) == false` | $O(K)$ на відсортованих даних |

### Топ-4 каверзних запитання на інтерв'ю

#### 1. Як `Sink.cancellationRequested()` взаємодіє зі сплітератором джерела даних?
- Під час протягування даних метод `copyInto()` у циклі викликає `spliterator.tryAdvance(wrappedSink)`. Перш ніж вилучити наступний елемент, сплітератор або проміжний `Sink` опитує `sink.cancellationRequested()`. Якщо прапорець дорівнює `true`, метод `tryAdvance` негайно припиняє цикл і повертає `false`, запобігаючи читанню зайвих даних.

#### 2. Чому в `parallelStream()` операція `findAny()` працює значно швидше, ніж `findFirst()`?
- `findAny()` не прив'язаний до вихідного порядку елементів (**Encounter Order**). Щойно будь-який робочий потік пулу `ForkJoinPool` знаходить збіг, він викликає `cancelLaterNodes()` і відразу повертає результат. `findFirst()` зобов'язаний повернути найперший елемент: якщо потік знайшов елемент у середині масиву, він зобов'язаний чекати завершення потоків, що обробляють початок масиву.

#### 3. У чому різниця між `allMatch()` на нескінченному стрімі, якщо предикат завжди повертає `true`, і якщо повернув `false`?
- Якщо хоча б один елемент дає `false`, `allMatch()` **негайно завершить роботу** і поверне `false` завдяки короткому замиканню.
- Якщо ж усі елементи задовольняють предикат (усі `true`), стрім **зависне в нескінченному циклі**, оскільки для доведення істинності твердження $\forall x \in S: P(x)$ на нескінченній множині $S$ необхідно перевірити нескінченну кількість елементів.

#### 4. Як поводяться `allMatch()` та `noneMatch()` на порожньому стрімі?
- На порожньому стрімі `allMatch(predicate)` повертає **`true`** (принцип вакуумної істинності в математичній логіці: немає жодного контрприкладу).
- `noneMatch(predicate)` на порожньому стрімі повертає **`true`** (немає жодного збігу).
- `anyMatch(predicate)` на порожньому стрімі повертає **`false`** (не знайдено жодного збігу).

---

### Типові помилки та Red Flags
- 🚩 Запуск `filter(predicate).findFirst()` на нескінченному стрімі з предикатом, який ніколи не виконається (вічний цикл CPU).
- 🚩 Використання `findFirst()` замість `findAny()` у `parallelStream()`, коли конкретний порядок елемента в колекції не має значення.
- 🚩 Спроба використовувати `filter()` замість `takeWhile()` на величезних відсортованих наборах даних.
- 🚩 Припущення, що `allMatch()` на порожньому стрімі поверне `false`.
