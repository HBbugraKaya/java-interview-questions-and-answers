# Что такое операции anyMatch(), allMatch(), noneMatch()

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
**`anyMatch()`**, **`allMatch()`** и **`noneMatch()`** — это **терминальные операции короткого замыкания (short-circuiting)**, которые проверяют элементы потока на соответствие заданному предикату `Predicate<T>` и возвращают примитивный результат `boolean`:

- **`anyMatch(Predicate)`** — возвращает `true`, если **хотя бы один** элемент удовлетворяет условию. Немедленно завершает работу при первом `true`.
- **`allMatch(Predicate)`** — возвращает `true`, если **все** элементы удовлетворяют условию. Немедленно завершает работу при первом `false`.
- **`noneMatch(Predicate)`** — возвращает `true`, если **ни один** элемент не удовлетворяет условию. Немедленно завершает работу при первом `true`.

---

### Примеры использования на Java 21

```java
import java.util.List;

public class MatchOperationsDemo {

    public record Account(String iban, boolean blocked, double balance) {}

    public static void main(String[] args) {
        List<Account> accounts = List.of(
            new Account("DE101", false, 1500.0),
            new Account("DE102", false, 240.0),
            new Account("DE103", true, -50.0)
        );

        // 1. anyMatch: Есть ли хоть один заблокированный счет?
        boolean hasBlocked = accounts.stream()
            .anyMatch(Account::blocked);
        System.out.println("Есть заблокированные: " + hasBlocked); // true

        // 2. allMatch: Все ли счета имеют положительный баланс?
        boolean allPositive = accounts.stream()
            .allMatch(a -> a.balance() > 0);
        System.out.println("Все в плюсе: " + allPositive); // false

        // 3. noneMatch: Правда ли, что нет счетов с отрицательным балансом ниже -1000?
        boolean noExtremeDebt = accounts.stream()
            .noneMatch(a -> a.balance() < -1000.0);
        System.out.println("Нет экстремальных долгов: " + noExtremeDebt); // true
    }
}
```

## 🟡 Middle Level

### Поведение на пустом стриме: концепция «Пустой истинности» (Vacuous Truth)

Классический вопрос на технических собеседованиях: **что вернет каждый из трех методов, если стрим не содержит ни одного элемента (`Stream.empty()`)?**

```java
Stream<String> emptyStream = Stream.empty();

boolean any  = Stream.empty().anyMatch(s -> true);  // false
boolean all  = Stream.empty().allMatch(s -> false); // true! (Даже с предикатом s -> false)
boolean none = Stream.empty().noneMatch(s -> true); // true!
```

#### Математическое обоснование:
1. **`anyMatch` ($\exists x \in S : P(x)$):** «Существует ли в множестве $S$ хотя бы один элемент, для которого истинен предикат $P$?». В пустом множестве $\emptyset$ элементов нет вообще, следовательно, подходящий элемент существовать не может $\rightarrow$ **`false`**.
2. **`allMatch` ($\forall x \in S : P(x)$):** «Для всех ли элементов множества $S$ истинен предикат $P$?». В математической логике утверждение считается истинным, если невозможно предъявить ни одного опровергающего контрпримера (**Vacuous Truth** — пустая истинность). Контрпримеров в пустом множестве нет $\rightarrow$ **`true`**.
3. **`noneMatch` ($\neg \exists x \in S : P(x)$):** «Правда ли, что ни один элемент множества $S$ не удовлетворяет предикату $P$?». Поскольку в множестве нет ни одного элемента, ни один элемент не может нарушить это утверждение $\rightarrow$ **`true`**.

---

### Эффективность по памяти: `anyMatch` против `filter().findFirst()`

Частый антипаттерн в коде:
```java
// ❌ Избыточные аллокации:
boolean exists = list.stream().filter(predicate).findFirst().isPresent();

// ✅ Оптимально:
boolean exists = list.stream().anyMatch(predicate);
```
- Вариант с `findFirst()` создает в куче объект-обертку `Optional<T>`, а также промежуточный узел конвейера `filter`.
- `anyMatch()` работает напрямую через булев флаг аккумулятора без создания объектов в heap ($O(1)$ allocations).

## 🔴 Senior Level

### Внутреннее устройство: `MatchOps`, `MatchKind` и `ForkJoinPool`

В исходном коде OpenJDK все три операции реализованы через единую абстракцию `MatchOps` и перечисление `MatchKind`:

```java
enum MatchKind {
    ANY(true, true),      // stopOnPredicateMatches = true, shortCircuitResult = true
    ALL(false, false),    // stopOnPredicateMatches = false, shortCircuitResult = false
    NONE(true, false);    // stopOnPredicateMatches = true, shortCircuitResult = false

    final boolean stopOnPredicateMatches;
    final boolean shortCircuitResult;
}
```

#### Механика в параллельных стримах (`parallelStream()`):
1. Вычисления оформляются в виде дерева задач **`MatchTask`** (наследник `ForkJoinTask`).
2. Задачи разделяют общий атомарный холдер результата (`SharedResult`).
3. Как только один из параллельных потоков находит замыкающее условие (например, воркер 2 нашел элемент `false` для `allMatch`):
   - Он выполняет CAS-запись в `SharedResult`.
   - Задача вызывает метод `cancelLaterNodes()`, рассылая сигнал отмены остальным дочерним подзадачам в `ForkJoinPool`.
   - Терминальная операция немедленно возвращает итоговый boolean, не дожидаясь завершения других воркеров.

---

### Поведение на бесконечных стримах (Infinite Streams)

1. **`Stream.generate(...).anyMatch(predicate)`**:
   - Безопасно завершится и вернет `true`, как только генератор выдаст первый элемент, удовлетворяющий условию.
2. **`Stream.iterate(1, n -> n + 1).allMatch(n -> n > 0)`**:
   - **Зависнет в бесконечном цикле (100% CPU)**. Поскольку предикат `n > 0` истинен для всех натуральных чисел, алгоритм будет вечно искать хотя бы один контрпример `false`, который никогда не появится.
3. **`Stream.iterate(1, n -> n + 1).allMatch(n -> n < 5)`**:
   - Быстро завершится и вернет `false` на числе `5`, так как найден контрпример.

## 🎯 Шпаргалка для интервью

### 30-секундный ответ
> «`anyMatch`, `allMatch` и `noneMatch` — терминальные операции короткого замыкания, возвращающие `boolean`. `anyMatch` останавливается при первом `true`, `allMatch` — при первом `false`, `noneMatch` — при первом `true`. На пустом стриме `anyMatch` возвращает `false`, а `allMatch` и `noneMatch` возвращают `true` (математический принцип Vacuous Truth). Они работают быстрее, чем `filter().findFirst().isPresent()`, так как не аллоцируют объект `Optional`. В `parallelStream` при нахождении короткого замыкания задача `MatchTask` отменяет остальные потоки через общий холдер результата.»

### Поведение операций на различных стримах

| Метод | Условие остановки | Результат на `Stream.empty()` | Поведение на бесконечном стриме, если условие НЕ найдено |
|---|---|---|---|
| **`anyMatch(p)`** | Первый `p.test(x) == true` | 🔴 **`false`** | 💥 Бесконечный цикл (ищет `true`) |
| **`allMatch(p)`** | Первый `p.test(x) == false` | 🟢 **`true`** | 💥 Бесконечный цикл (ищет `false`) |
| **`noneMatch(p)`** | Первый `p.test(x) == true` | 🟢 **`true`** | 💥 Бесконечный цикл (ищет `true`) |

### Топ-4 каверзных вопроса на интервью

#### 1. Что вернет `Stream.empty().allMatch(x -> false)` и почему?
- Метод вернет **`true`**. По законам математической логики утверждение с квантором всеобщности ($\forall x \in S : P(x)$) над пустым множеством $S = \emptyset$ считается истинным, так как не существует ни одного контрпримера в множестве, который нарушал бы предикат (принцип Vacuous Truth).

#### 2. В чем разница между `stream.anyMatch(p)` и `stream.filter(p).findAny().isPresent()`?
- Семантически они эквивалентны, но `anyMatch(p)` эффективнее: он не создает промежуточный узел конвейера `filter` и не аллоцирует объект-контейнер `Optional<T>` в куче (Heap), напрямую возвращая примитивный `boolean`.

#### 3. Как прерываются другие параллельные потоки в `parallelStream().allMatch()` при нахождении `false`?
- Используется внутренний класс `MatchTask`. Первый поток, обнаруживший элемент, не удовлетворяющий предикату (`false`), атомарно записывает флаг завершения в разделяемый объект `SharedResult` и вызывает метод отмены `cancelLaterNodes()`, прерывая обработку очередей в `ForkJoinPool`.

#### 4. Может ли `allMatch()` гарантировать строгий порядок проверки элементов?
- В последовательном стриме элементы проверяются строго в порядке источника (Encounter Order) до первого `false`.
- В параллельном стриме элементы проверяются в разных потоках одновременно. Если несколько элементов нарушают условие, стрим прервется на том элементе, который первым успеет вычислить любой из свободных рабочих потоков.

---

### Типичные ошибки и Red Flags
- 🚩 Уверенность в том, что `allMatch()` на пустом стриме вернет `false`.
- 🚩 Использование `filter().findFirst().isPresent()` вместо лаконичного и быстрого `anyMatch()`.
- 🚩 Запуск `allMatch()` или `noneMatch()` на бесконечном стриме с предикатом, не имеющим точек короткого замыкания.
- 🚩 Размещение тяжелых побочных эффектов внутри предикатов match-операций.
