# Можно ли переопределить конструктор в Record

---

## 🟢 Junior Level

**Да, можно.** В Java для `Record` поддерживаются три формы конструкторов:

1. **Компактный конструктор (`Compact Constructor`)**: специализированная форма без круглых скобок со списком аргументов, предназначенная для валидации и нормализации данных:
   ```java
   public record User(String name, int age) {
       public User {
           if (age < 0) {
               throw new IllegalArgumentException("Age cannot be negative: " + age);
           }
           name = name.trim(); // нормализация
       }
   }
   ```
2. **Явный канонический конструктор**: полное объявление конструктора со всеми параметрами из заголовка:
   ```java
   public record Point(int x, int y) {
       public Point(int x, int y) {
           this.x = x;
           this.y = y;
       }
   }
   ```
3. **Вторичные (дополнительные) конструкторы**: конструкторы с другим набором параметров, которые **в обязательном порядке первой же строкой вызывают канонический конструктор через `this(...)`**:
   ```java
   public record User(String name, int age) {
       public User(String name) {
           this(name, 18); // Обязательный вызов this(...)
       }
   }
   ```

### Главное правило

Любой вторичный конструктор **обязан делегировать** инициализацию другому конструктору через `this(...)`, пока цепочка не дойдет до канонического конструктора. Вызов `super(...)` в записях запрещен.

## 🟡 Middle Level

### 1. Как устроен компактный конструктор

Компактный конструктор — это уникальная фича `Record`. Он объявляется без списка параметров: `public User { ... }`.

**Что делает компилятор под капотом:**
1. Неявно передает в тело конструктора параметры, соответствующие компонентам заголовка (`name`, `age`).
2. Вставляет код валидации, написанный разработчиком.
3. В самом конце метода **автоматически вставляет финальное присваивание полей**:
   ```java
   this.name = name;
   this.age = age;
   ```

```java
public record NormalizedEmail(String value) {
    public NormalizedEmail {
        Objects.requireNonNull(value, "Email must not be null");
        // Переменная value здесь — это не поле, а неявный параметр метода!
        value = value.toLowerCase().trim();
        // В конце компилятор автоматически сделает: this.value = value;
    }
}
```

> [!WARNING]
> Внутри компактного конструктора **запрещено обращаться к полям через `this.field`**! Попытка написать `this.value = value;` вызовет ошибку компиляции: *«Cannot assign a value to final variable value»*.

### 2. Защитное копирование (Defensive Copy) в конструкторе

Если компонент `Record` — мутабельная коллекция или массив, инициализация должна создавать защитную неизменяемую копию:

```java
public record Team(String name, List<String> members) {
    public Team {
        Objects.requireNonNull(name);
        // Защита от мутаций: создаем по-настоящему неизменяемый список
        members = List.copyOf(members);
    }
}
```

## 🔴 Senior Level

### Правила спецификации языка (JLS §8.10.4)

Спецификация языка Java накладывает строгие правила на конструкторы записей:

#### 1. Запрет одновременного объявления компактного и явного канонического конструктора
В одном `record` **нельзя** объявить и компактный, и явный канонический конструктор:
```java
public record Point(int x, int y) {
    public Point { ... } // Компактный
    // ❌ Ошибка компиляции: duplicate method Point(int, int)
    public Point(int x, int y) { ... } 
}
```
Компактный конструктор компилируется непосредственно в тело канонического конструктора. Наличие обоих приводит к конфликту дублирования метода с одинаковой сигнатурой.

#### 2. Ограничения модификаторов доступа
Модификатор доступа канонического (или компактного) конструктора **не может быть более строгим, чем у самого Record**:
```java
public record User(String name) {
    // ❌ Ошибка компиляции: canonical constructor cannot have more restrictive access than the record class
    private User(String name) {
        this.name = name;
    }
}
```
Если класс `public`, то канонический конструктор обязан быть `public`. Если класс `package-private`, конструктор может быть `public` или `package-private`.

Однако **вторичные конструкторы могут иметь любой модификатор**, включая `private`:
```java
public record Token(String value) {
    // Канонический конструктор неявно public
    
    // Вторичный конструктор может быть private:
    private Token(byte[] raw) {
        this(Base64.getEncoder().encodeToString(raw));
    }

    public static Token fromBytes(byte[] raw) {
        return new Token(raw);
    }
}
```

#### 3. Семантика исключений (Throws Clause)
- Компактный конструктор **не может содержать секцию `throws`**:
  ```java
  public record FileData(String path) {
      // ❌ Ошибка компиляции: throws clause not allowed on compact constructor
      public FileData throws IOException { ... }
  }
  ```
  Любые ошибки в компактном конструкторе должны выбрасываться как **`RuntimeException`** (например, `IllegalArgumentException`, `NullPointerException`).
- Явный канонический конструктор может объявить `throws CheckedException`, но это считается грубым антипаттерном, так как ломает функциональное создание объектов и десериализацию.

## 4 Tricky Questions

### 1. Можно ли в одном Record объявить одновременно компактный конструктор и явный канонический конструктор?
**Ответ:** 
**Нет, это приведет к ошибке компиляции.** 

Компактный конструктор — это просто альтернативная синтаксическая форма записи канонического конструктора. На этапе генерации байткода компилятор создает из компактного конструктора обычный конструктор с сигнатурой `(ComponentType1, ComponentType2, ...)`. Попытка объявить оба конструктора одновременно означает создание двух методов с идентичной сигнатурой, что вызовет ошибку компилятора: `«Variable-arity method or duplicate method in type»`.

### 2. Может ли канонический конструктор Record иметь модификатор доступа более строгий, чем сам класс (например, `private` конструктор у `public record`)?
**Ответ:** 
**Нет, не может.** 

Согласно спецификации JLS §8.10.4, модификатор доступа канонического конструктора должен быть не менее доступным, чем модификатор доступа самого класса `Record`. Для `public record` канонический конструктор обязан быть `public`. Это требование обусловлено тем, что Record спроектирован как прозрачный контейнер данных: любой код, имеющий доступ к типу записи, должен иметь право сконструировать его из компонентов. 

Вторичные (неканонические) конструкторы при этом могут быть `private`.

### 3. Разрешено ли внутри компактного конструктора обращаться к полям через `this.field` (например, `this.x = 10`)?
**Ответ:** 
**Нет, обращение к полям через `this.` внутри компактного конструктора запрещено компилятором.** 

В компактном конструкторе код разработчика выполняется **до** инициализации финальных полей объекта. Идентификаторы компонентов (`x`, `y`) в теле компактного конструктора ссылаются на **неявные локальные параметры**, а не на поля экземпляра. Вы можете переприсвоить значение параметру (`x = Math.max(0, x);`), и компилятор сам сгенерирует код `this.x = x;` в самом конце конструктора. Прямая попытка чтения или записи `this.x` вызовет ошибку компиляции.

### 4. Можно ли во вторичном конструкторе Record вызвать `super(...)` вместо `this(...)`?
**Ответ:** 
**Категорически нет.** 

Вторичный конструктор `Record` обязан первой строкой вызывать другой конструктор этого же класса через `this(...)`. Прямой вызов `super(...)` запрещен. Единственным суперклассом для записей является `java.lang.Record`, чей конструктор вызывается компилятором автоматически только из канонического конструктора.

## 🎯 Шпаргалка для интервью

### 3 вида конструкторов в Record

| Тип конструктора | Сигнатура | Особенности |
| :--- | :--- | :--- |
| **Компактный** | `public User { ... }` | Без параметров. Валидация и нормализация. Присваивание полей скрыто. |
| **Канонический** | `public User(String name, int age) { ... }` | Полный список параметров. Ручное присваивание `this.x = x`. |
| **Вторичный** | `public User(String name) { this(name, 0); }` | Любые параметры. **Обязан вызывать `this(...)`**. |

### Главные инварианты
1. Либо компактный, либо канонический конструктор — **но никогда оба сразу**.
2. В компактном конструкторе: пишем `name = name.trim()`, но **не** `this.name = ...`.
3. Модификатор доступа канонического конструктора **не может быть уже**, чем у класса.
4. Вызов `super(...)` запрещен — только `this(...)`.
5. Для защитного копирования мутабельных коллекций используйте `List.copyOf()`, а не `new ArrayList<>()`.
