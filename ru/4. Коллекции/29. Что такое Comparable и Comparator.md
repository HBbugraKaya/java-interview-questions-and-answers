# Что такое Comparable и Comparator

---

## 🟢 Junior Level

### 1. В чём разница: простое объяснение

Интерфейсы **`Comparable`** и **`Comparator`** используются в Java для сравнения и сортировки объектов, но решают эту задачу на разных архитектурных уровнях:

- **`Comparable` («Сравнимый сам по себе»):** реализуется **внутри** самого класса сущности. Задает его естественный порядок сортировки по умолчанию (Natural Ordering).
- **`Comparator` («Внешний сравнитель / Судья»):** создается как **отдельный класс или лямбда-выражение**. Позволяет реализовать произвольное количество альтернативных стратегий сортировки без изменения исходного класса.

```java
// 1. Использование Comparable (естественный порядок по ID)
class Employee implements Comparable<Employee> {
    private int id;
    private String name;

    public Employee(int id, String name) { this.id = id; this.name = name; }

    @Override
    public int compareTo(Employee other) {
        return Integer.compare(this.id, other.id); // Сравнение по ID
    }
}

List<Employee> list = new ArrayList<>();
Collections.sort(list); // Сортирует по natural order (через compareTo)

// 2. Использование Comparator (альтернативный порядок по имени)
Comparator<Employee> byName = (e1, e2) -> e1.name.compareTo(e2.name);
list.sort(byName); // Сортирует по имени
```

---

### 2. Сводная таблица различий

| Характеристика | `Comparable<T>` | `Comparator<T>` |
| :--- | :--- | :--- |
| **Пакет** | `java.lang` | `java.util` |
| **Метод интерфейса** | `int compareTo(T o)` | `int compare(T o1, T o2)` |
| **Где реализуется** | Внутри сравниваемого класса | В отдельном классе, анонимном классе или лямбде |
| **Количество стратегий** | Только **одна** (порядок по умолчанию) | **Неограниченно** много |
| **Модификация класса** | Требует исходного кода класса | Не требует (работает со сторонними библиотеками) |
| **Вызов сортировки** | `Collections.sort(list)` | `list.sort(comparator)` |

## 🟡 Middle Level

### 1. Функциональный API комбинаторов (Java 8+)

В Java 8 `Comparator` стал функциональным интерфейсом и получил богатый набор фабричных методов и комбинаторов, позволяющих выстраивать сложные многоуровневые правила сортировки декларативно:

```java
List<Employee> staff = getEmployees();

// Цепочка сравнений: сначала по фамилии, затем по имени, затем по убыванию зарплаты:
Comparator<Employee> complexComparator = Comparator
    .comparing(Employee::getLastName)
    .thenComparing(Employee::getFirstName)
    .thenComparingDouble(Employee::getSalary).reversed();

staff.sort(complexComparator);
```

#### Безопасная работа со значениями `null`:
```java
// Размещение null-значений в самом конце списка:
Comparator<Employee> safeComparator = Comparator.comparing(
    Employee::getName, 
    Comparator.nullsLast(String::compareTo)
);
```

### 2. Смертельная ловушка: вычитание чисел в компараторе

Один из самых распространенных багов в коде — использование арифметического вычитания для чисел:

```java
// ❌ ГРУБЕЙШАЯ ОШИБКА (Integer Overflow):
Comparator<User> badComparator = (u1, u2) -> u1.id - u2.id;
```

**Почему это сломает сортировку:**
Если `u1.id = -2_000_000_000`, а `u2.id = 1_000_000_000`, операция вычитания даст:
`-2_000_000_000 - 1_000_000_000 = -3_000_000_000`.
Значение выходит за пределы диапазона `int` (`Integer.MIN_VALUE = -2_147_483_648`), происходит **целочисленное переполнение (Underflow)**, и результат вычитания становится положительным числом `1_294_967_296`! Компаратор посчитает, что $u1 > u2$, полностью разрушив порядок сортировки.

> [!TIP]
> Всегда используйте статические методы сравнения примитивов:
> `Integer.compare(a, b)`, `Long.compare(a, b)`, `Double.compare(a, b)` или специализированные методы `comparingInt()`, `comparingLong()`.

## 🔴 Senior Level

### 1. Строгий математический контракт и исключение Timsort

Сортировка коллекций в Java реализована на алгоритме **Timsort** (гибрид сортировки вставками и сортировки слиянием). Timsort жестко опирается на аксиомы математического порядка. Компаратор обязан соблюдать следующие свойства:

1. **Антисимметричность:** $\operatorname{sgn}(\operatorname{compare}(x, y)) == -\operatorname{sgn}(\operatorname{compare}(y, x))$.
2. **Транзитивность:** если $\operatorname{compare}(x, y) > 0$ и $\operatorname{compare}(y, z) > 0$, то обязательно $\operatorname{compare}(x, z) > 0$.
3. **Транзитивность эквивалентности:** если $\operatorname{compare}(x, y) == 0$ и $\operatorname{compare}(y, z) == 0$, то $\operatorname{compare}(x, z) == 0$.

#### Как вызвать аварийное падение Timsort:
Если компаратор нарушает транзитивность или антисимметричность:
```java
// ❌ НАРУШЕНИЕ АНТИСИММЕТРИЧНОСТИ:
// Для двух равных элементов возвращает -1 вместо 0!
Comparator<Integer> broken = (a, b) -> a > b ? 1 : -1;
```
При запуске `list.sort(broken)` на достаточно большом наборе данных ($\ge 32$ элементов) Timsort обнаружит противоречие в границах отсортированных последовательностей (Run boundaries) и выбросит исключение:
`java.lang.IllegalArgumentException: Comparison method violates its general contract!`

### 2. Согласованность с `equals()` и поведение в `TreeSet` / `TreeMap`

Официальная спецификация интерфейса `Comparable` настоятельно рекомендует:
> `(x.compareTo(y) == 0) == (x.equals(y))`

Если этот контракт нарушен, коллекции, основанные на деревьях (`TreeSet`, `TreeMap`), будут вести себя некорректно:
- `TreeSet` и `TreeMap` **не вызывают `equals()`**; они определяют идентичность ключей исключительно по условию `compareTo(a, b) == 0`.
- Если у двух различных объектов `compareTo() == 0`, второй объект будет молча отброшен деревом как дубликат, даже если по бизнес-логике `equals()` они абсолютно разные.

---

### 3. Оптимизация GC: примитивные компараторы

При сортировке больших коллекций (миллионы записей) использование объектных методов приводит к массовому автобоксингу:

```java
// ❌ Боксинг: геттер возвращает int, boxing упаковывает в Integer, Comparator распаковывает:
Comparator.comparing(User::getAge);

// ✅ Ноль аллокаций: метод comparingInt работает напрямую с примитивными регистрами CPU:
Comparator.comparingInt(User::getAge);
```
Использование `comparingInt()` исключает генерацию мусорных объектов в Heap и ускоряет сортировку на 30–50%.

## 🎯 Шпаргалка для интервью

### 30-секундный ответ (Elevator Pitch)
> «`Comparable` определяет естественный порядок сортировки сущности по умолчанию (`Natural Order`) через единственный метод `compareTo(T o)` внутри самого класса. `Comparator` — это функциональный интерфейс `compare(T o1, T o2)`, позволяющий задавать внешние настраиваемые стратегии сортировки через лямбды и цепочки комбинаторов (`comparing`, `thenComparing`). При написании компараторов категорически запрещено использовать вычитание чисел `o1.id - o2.id` из-за риска переполнения примитивов — нужно использовать `Integer.compare()`. Нарушение математического контракта транзитивности приведет к выбросу `IllegalArgumentException` в алгоритме Timsort».

### 3 каверзных вопроса на интервью с ответами

#### 1. Почему компаратор `(a, b) -> a > b ? 1 : -1` выбросит `IllegalArgumentException` при сортировке списка из 100 элементов?
**Ответ:** Данный компаратор нарушает свойство рефлексивности и антисимметричности: когда $a == b$, он возвращает `-1` вместо положенного `0`. В результате получается, что $a < b$ и одновременно $b < a$. При слиянии подмассивов в алгоритме Timsort возникает логическое противоречие в упорядоченности стека серий (runs), что приводит к гарантированному выбросу `java.lang.IllegalArgumentException: Comparison method violates its general contract!`.

#### 2. В чём разница между `Collections.sort(list, comparator)` и `list.sort(comparator)` в Java 8+?
**Ответ:** Начиная с Java 8, метод `Collections.sort()` просто делегирует вызов default-методу `list.sort()`. В классе `ArrayList` метод `list.sort(c)` сортирует внутренний массив `elementData` напрямую на месте (in-place) через `Arrays.sort()`. Это быстрее, чем старая реализация Java 7, которая сначала копировала элементы в отдельный массив, сортировала его и затем перезаписывала список через `ListIterator`.

#### 3. Что произойдет, если положить объект в `TreeSet`, если его класс НЕ реализует `Comparable`, и компаратор в конструктор передан не был?
**Ответ:** При попытке вставить первый элемент `treeSet.add(e)` в пустой сет в современных версиях Java (начиная с Java 7) сразу произойдет попытка приведения типа `((Comparable<? super K>) key).compareTo(...)`. Поскольку класс не реализует интерфейс, будет немедленно выброшено исключение `ClassCastException`.

---

### Типичные ошибки и Red Flags

- ❌ **Использование арифметического вычитания в `compare`:** Приводит к переполнению целых чисел и хаотичному порядку сортировки.
- ❌ **Возврат -1 вместо 0 для равных элементов:** Нарушает антисимметричность и ломает Timsort.
- ❌ **Несогласованность `compareTo()` и `equals()`:** Ведет к необъяснимой потере данных в `TreeSet` и `TreeMap`.
- ❌ **Отсутствие обработки `null`:** Попытка вызвать `o1.compareTo(o2)` при `o1 == null` завершится `NullPointerException`.
