# Что делает операция flatMap()

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
**`flatMap()`** — это промежуточная (intermediate) операция Stream API, которая преобразует каждый элемент исходного потока в отдельный независимый поток с помощью функции-маппера (`T -> Stream<R>`), а затем «сплющивает» (flatten) все полученные подпотоки в единый результирующий поток `Stream<R>`.

Главное отличие от обычного `map()`:
- **`map()`** выполняет отображение **«один к одному»** (`T -> R`), возвращая поток элементов типа `R` (если маппер возвращает список, на выходе будет `Stream<List<R>>`).
- **`flatMap()`** выполняет отображение **«один ко многим»** (или «один к нулю») (`T -> Stream<R>`), объединяя все вложенные элементы в плоскую структуру `Stream<R>`.

---

### Базовые примеры на Java 21

```java
import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

public class FlatMapBasicsDemo {

    public record OrderItem(String product, int quantity, double price) {}
    public record Order(long id, List<OrderItem> items) {}

    public static void main(String[] args) {
        List<Order> orders = List.of(
            new Order(101L, List.of(
                new OrderItem("Клавиатура", 1, 3500.0),
                new OrderItem("Мышь", 2, 1800.0)
            )),
            new Order(102L, List.of(
                new OrderItem("Монитор", 1, 24000.0),
                new OrderItem("Мышь", 1, 1800.0)
            ))
        );

        // 1. Извлечение всех купленных товаров из всех заказов в единый список
        List<String> allProducts = orders.stream()
            .flatMap(order -> order.items().stream()) // Stream<Order> -> Stream<OrderItem>
            .map(OrderItem::product)
            .toList();

        System.out.println("Все позиции: " + allProducts);
        // [Клавиатура, Мышь, Монитор, Мышь]

        // 2. Получение уникальных товаров из заказов
        Set<String> uniqueProducts = orders.stream()
            .flatMap(order -> order.items().stream())
            .map(OrderItem::product)
            .collect(Collectors.toSet());

        System.out.println("Уникальные товары: " + uniqueProducts);
        // [Клавиатура, Мышь, Монитор]
    }
}
```

## 🟡 Middle Level

### Особенности работы и примитивные специализации

Сигнатура метода в интерфейсе `Stream<T>`:
```java
<R> Stream<R> flatMap(Function<? super T, ? extends Stream<? extends R>> mapper);
```

#### Ключевые аспекты поведения:
1. **Фильтрация через `Stream.empty()`:** Если функция возвращает пустой поток `Stream.empty()`, исходный элемент бесследно исключается из результирующего потока (отображение «один к нулю»).
2. **Защита от NPE:** Функция-маппер **никогда не должна возвращать `null`**. Возврат `null` немедленно приводит к `NullPointerException` во время исполнения конвейера.
3. **Примитивные специализации:** Для предотвращения накладных расходов на автобоксинг используются методы `flatMapToInt()`, `flatMapToLong()`, `flatMapToDouble()`.

```java
import java.util.List;
import java.util.Optional;
import java.util.stream.IntStream;

public class FlatMapAdvancedDemo {

    public static void main(String[] args) {
        // Примитивная специализация flatMapToInt (без упаковки в Integer)
        List<String> rawTokens = List.of("10,20,30", "40,50");
        int sum = rawTokens.stream()
            .flatMapToInt(s -> {
                String[] parts = s.split(",");
                return IntStream.range(0, parts.length).map(i -> Integer.parseInt(parts[i].trim()));
            })
            .sum();
        System.out.println("Сумма: " + sum); // 150

        // Интеграция с Optional (Java 9+): разворачивание присутствующих значений
        List<Optional<String>> optionalList = List.of(
            Optional.of("Alfa"),
            Optional.empty(),
            Optional.of("Beta")
        );

        List<String> presentValues = optionalList.stream()
            .flatMap(Optional::stream) // Optional::stream разворачивает в Stream с 0 или 1 элементом
            .toList();
        System.out.println("Присутствующие значения: " + presentValues); // [Alfa, Beta]
    }
}
```

## 🔴 Senior Level

### Внутреннее устройство: `ReferencePipeline`, `Sink` и потеря характеристик `Spliterator`

Метод `flatMap()` возвращает анонимный подкласс `ReferencePipeline.StatelessOp`. Когда терминальная операция запускает обработку, создается цепочка объектов `Sink`.

Для `flatMap` входящий `Sink.accept(T t)` устроен следующим образом:
1. Вызывает функцию `mapper.apply(t)`.
2. Получает вложенный `Stream<R> resultStream`.
3. Если `resultStream != null`, запускает обход его `Spliterator` и для каждого вложенного элемента вызывает `downstream.accept(r)`.
4. В блоке `try-finally` гарантированно вызывает `resultStream.close()`.

```
Pipeline Flow:
[Order 1] ---> flatMap Sink.accept(order1)
                  ├── mapper.apply(order1) -> subStream
                  ├── subStream.forEachRemaining(downstream::accept) -> [Item 1, Item 2]
                  └── subStream.close()
[Order 2] ---> flatMap Sink.accept(order2)
                  ├── mapper.apply(order2) -> subStream
                  ├── subStream.forEachRemaining(downstream::accept) -> [Item 3]
                  └── subStream.close()
```

#### Проблема сброса флагов `SIZED` и `SUBSIZED`:
Сплитератор, порожденный `flatMap`, **теряет флаги `SIZED` и `SUBSIZED`**, а его `estimateSize()` становится равным `Long.MAX_VALUE`. Рантайм стрима принципиально не может заранее знать, сколько элементов сгенерирует каждый вложенный поток.

**Последствия для параллельных стримов (`parallelStream()`):**
- Невозможно оптимально сбалансировать задачи в `ForkJoinPool`.
- Рантайм стрима вынужден разбивать входной массив, но дерево слияния не знает точных границ и аллоцирует буферы переменного размера (`SpinedBuffer`).
- Параллельный `flatMap` практически всегда показывает существенно меньшее ускорение по сравнению с параллельным `map` или `filter`.

### Альтернатива в Java 16+: `Stream.mapMulti()`

Главная архитектурная проблема классического `flatMap` — **давление на GC (Garbage Collector Overhead)**. Для *каждого* элемента входного потока создается промежуточный объект `Stream`, его внутренний сплитератор и узел конвейера, даже если внутри находится всего 1–2 элемента.

В Java 16 появился метод `mapMulti()`, реализующий модель push-потребления через `Consumer`:

```java
<R> Stream<R> mapMulti(BiConsumer<? super T, ? super Consumer<R>> mapper);
```

Сравнение производительности и аллокаций:

```java
import java.util.List;

public class MapMultiComparisonDemo {

    public record Department(String name, List<String> employees) {}

    public static void main(String[] args) {
        List<Department> departments = List.of(
            new Department("IT", List.of("Иван", "Петр")),
            new Department("Sales", List.of("Анна", "Ольга"))
        );

        // 1. Классический flatMap: аллоцирует Stream для каждого Department
        List<String> listFlatMap = departments.stream()
            .flatMap(d -> d.employees().stream())
            .toList();

        // 2. Высокопроизводительный mapMulti (Java 16+):
        // Ноль аллокаций промежуточных объектов Stream!
        List<String> listMapMulti = departments.stream()
            .<String>mapMulti((dept, consumer) -> {
                for (String employee : dept.employees()) {
                    consumer.accept(employee);
                }
            })
            .toList();

        System.out.println("mapMulti результат: " + listMapMulti);
    }
}
```

> **Senior Insight:** В high-load сервисах с обработкой миллионов сообщений замена `flatMap` на `mapMulti` устраняет миллионы эфемерных объектов `Stream` и `Spliterator`, снижая частоту пауз Young Gen GC.

### Управление ресурсами и `AutoCloseable`

Если вложенный поток открывает системные ресурсы (файлы через `Files.lines()`, соединения с БД или сетевые сокеты), стрим обязан быть закрыт через `try-with-resources`.

Stream API связывает жизненный цикл вложенных стримов:
```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.stream.Stream;

public class ResourceClosingFlatMapDemo {

    public static void readAllFiles(List<Path> files) {
        // Внешний try-with-resources закрывает внешний стрим
        try (Stream<Path> pathStream = files.stream()) {
            pathStream.flatMap(path -> {
                try {
                    // Возвращаемый Stream<String> будет автоматически закрыт
                    // реализацией flatMap сразу после исчерпания его сплитератора!
                    return Files.lines(path);
                } catch (IOException e) {
                    return Stream.empty();
                }
            }).forEach(System.out::println);
        }
    }
}
```
`ReferencePipeline.StatelessOp` внутри `flatMap` регистрирует обработчики закрытия: если внешний поток прерывается исключением или закрывается, закрываются и вложенные активные потоки.

## 🎯 Шпаргалка для интервью

### 30-секундный ответ
> «`flatMap()` — промежуточная операция с семантикой 1-ко-многим. Она принимает функцию `T -> Stream<R>` и схлопывает полученные подпотоки в единый плоский `Stream<R>`. В отличие от `map()`, возвращающего структуру «как есть», `flatMap()` разворачивает вложенные коллекции. Начиная с Java 16, для избежания аллокаций промежуточных стримов рекомендуется использовать `mapMulti()`. Важно помнить, что `flatMap()` сбрасывает флаг `SIZED`, что делает параллельные стримы менее эффективными.»

---

### Различия `map()`, `flatMap()` и `mapMulti()`

| Характеристика | `map()` | `flatMap()` | `mapMulti()` (Java 16+) |
|---|---|---|---|
| **Отношение** | 1 к 1 | 1 к $N$ (где $N \ge 0$) | 1 к $N$ (где $N \ge 0$) |
| **Сигнатура маппера** | `T -> R` | `T -> Stream<R>` | `(T, Consumer<R>) -> void` |
| **Аллокация объектов Stream** | Нет | Создает `Stream` на каждый элемент | **Нет** (использует императивный Consumer) |
| **Сохранение размера (`SIZED`)** | Да | **Нет** (сбрасывает в `Long.MAX_VALUE`) | **Нет** |
| **Эффективность в parallel** | Высокая | Низкая (неравномерный сплит) | Средняя |

### Топ-4 каверзных вопроса на интервью

#### 1. Почему `flatMap` сбрасывает флаг `SIZED` в стриме и как это ухудшает производительность в parallelStream?
- Флаг `SIZED` означает, что точное количество элементов известно до начала обработки. Так как лямбда `flatMap` может вернуть стрим любого размера (пустой, из 1 элемента или из 10 000 элементов), рантайм не может вычислить `count()` без полного вычисления всех элементов.
- В параллельных стримах деление задач в `Spliterator` (метод `trySplit()`) опирается на размер подзадачи. Потеря размера приводит к неравномерному разделению чанков между потоками `ForkJoinPool` и необходимости динамически переаллоцировать узлы связных буферов (`SpinedBuffer`).

#### 2. В чём преимущество метода `Stream.mapMulti()` (Java 16+) перед `flatMap()`, и как он устроен внутри?
- `mapMulti()` устраняет накладные расходы на аллокацию промежуточных объектов `Stream` для каждого входного элемента.
- Вместо возврата нового `Stream<R>`, пользовательская лямбда получает элемент и системный `Consumer<R>`. Она передает элементы напрямую в downstream-приемник (`consumer.accept(...)`) через обычный цикл `for`. Это значительно снижает нагрузку на сборщик мусора (GC) в высоконагруженных сценариях.

#### 3. Что произойдёт, если лямбда в `flatMap` вернет `null` вместо `Stream`? Как правильно обрабатывать отсутствующие значения?
- Метод немедленно выбросит `NullPointerException` при попытке рантайма вызвать `stream.spliterator()`.
- Если для элемента нет значений, лямбда обязана возвращать `Stream.empty()`. В Java 9+ при работе с `Optional` рекомендуется использовать вызов `optional.stream()`.

#### 4. Как закрываются ресурсы (`AutoCloseable`), открытые внутри стримов, возвращаемых лямбдой `flatMap`?
- Реализация `flatMap` в `ReferencePipeline` оборачивает потребление каждого вложенного стрима в конструкцию `try-finally`. Как только элементы подпотока вычитаны, рантайм вызывает `subStream.close()`. Если стрим был получен через `Files.lines()`, файловый дескриптор корректно освобождается.

---

### Типичные ошибки и Red Flags
- 🚩 Возврат `null` из лямбды `flatMap()` вместо `Stream.empty()`, приводящий к NPE в рантайме.
- 🚩 Использование `flatMap()` там, где достаточно обычного `map()` (например, просто для вызова геттера поля).
- 🚩 Массовое создание коротких стримов `Stream.of(item)` внутри `flatMap` под высокой нагрузкой вместо использования `mapMulti()`.
- 🚩 Попытка параллелизации тяжелых вычислений через `flatMap().parallel()`, не проверив профилировщиком перекос по потокам ForkJoinPool из-за потери `SIZED`.
