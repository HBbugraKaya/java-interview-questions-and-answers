# Что такое lazy evaluation в Stream

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
**Lazy Evaluation (Ленивые вычисления / Отложенное выполнение)** — это стратегия вычислений в Stream API, при которой вызов промежуточных (intermediate) операций (`filter`, `map`, `peek`, `sorted`) **не выполняет реальную обработку данных в момент объявления**, а лишь конструирует план будущего конвейера обработки.

Реальное считывание и преобразование элементов начинается **только тогда, когда вызывается терминальная (terminal) операция** (`collect()`, `toList()`, `forEach()`, `count()`, `findFirst()`). Если терминальная операция не вызвана, ни одна строчка кода внутри промежуточных лямбд никогда не выполнится.

---

### Наглядный пример на Java 21

```java
import java.util.List;
import java.util.stream.Stream;

public class LazyEvaluationDemo {

    public static void main(String[] args) {
        List<String> words = List.of("яблоко", "апельсин", "ананас", "банан");

        // 1. Промежуточные операции — здесь НЕ происходит никакой фильтрации и трансформации:
        Stream<String> plan = words.stream()
            .filter(w -> {
                System.out.println("[Filter] " + w);
                return w.startsWith("а");
            })
            .map(w -> {
                System.out.println("[Map] " + w);
                return w.toUpperCase();
            });

        System.out.println(">>> Промежуточный конвейер объявлен, терминальная операция НЕ вызывалась <<<");

        // 2. Только при вызове терминальной операции запускается обработка:
        System.out.println(">>> Вызываем toList() <<<");
        List<String> result = plan.toList();
        System.out.println("Результат: " + result);
    }
}
```

**Вывод программы:**
```
>>> Промежуточный конвейер объявлен, терминальная операция НЕ вызывалась <<<
>>> Вызываем toList() <<<
[Filter] яблоко
[Filter] апельсин
[Map] апельсин
[Filter] ананас
[Map] ананас
[Filter] банан
Результат: [АПЕЛЬСИН, АНАНАС]
```

## 🟡 Middle Level

### Вертикальное (Vertical) исполнение и Loop Fusion

В отличие от традиционных цепочек методов в коллекциях (где каждый шаг создает новый промежуточный список), Stream API реализует **вертикальный проход (Vertical Execution / Loop Fusion)**:

```
Горизонтальное выполнение (Коллекции):
[Исходный массив 1M] ──► Filter ──► [Промежуточный List 1M] ──► Map ──► [Итоговый List]
                                     ▲
                               Память $O(N)$

Вертикальное выполнение (Stream API — Loop Fusion):
Элемент 1 ──► [Filter: OK]   ──► [Map] ──► [Collect]
Элемент 2 ──► [Filter: FAIL] ──► (отброшен сразу)
Элемент 3 ──► [Filter: OK]   ──► [Map] ──► [Collect]
```

#### Преимущества модели Loop Fusion:
1. **Нулевые затраты памяти ($O(1)$ allocations):** Не создаются промежуточные структуры данных между вызовами `filter` и `map`.
2. **Кэш-локальность CPU:** Один элемент сразу проходит через все операции, пока его данные находятся в быстрых регистрах и кэше L1/L2 процессора.
3. **Возможность раннего выхода (Short-circuiting):** Если вызвать `.findFirst()`, обработка остановится на первом подходящем элементе, а остальные 999 999 элементов даже не будут прочитаны.

## 🔴 Senior Level

### Бесконечные стримы (Infinite Streams) благодаря ленивости

Ленивость позволяет создавать бесконечные потоки данных через `Stream.generate()` и `Stream.iterate()`:

```java
import java.util.List;
import java.util.UUID;
import java.util.stream.Stream;

public class InfiniteLazyStreamDemo {

    public static void main(String[] args) {
        // Бесконечный поток генерации UUID
        List<UUID> zeroPrefixTokens = Stream.generate(UUID::randomUUID)
            .filter(uuid -> uuid.toString().startsWith("00"))
            .limit(3) // Терминальный шорт-циркуит: прерывает бесконечный стрим!
            .toList();

        System.out.println("Сгенерировано 3 токена: " + zeroPrefixTokens);
    }
}
```

#### Почему это работает:
- `Stream.generate()` не генерирует бесконечное количество элементов в память.
- Метод `limit(3)` запрашивает у сплитератора элементы по одному («pull-модель»). Как только получены 3 отфильтрованных элемента, конвейер закрывается.

> **Senior Warning:** Если на бесконечный стрим повесить промежуточную операцию с состоянием без ограничения (например, `stream.filter(...).sorted()`), программа войдет в **бесконечный цикл** и исчерпает память (`OutOfMemoryError`), так как `sorted()` обязан сначала прочитать ВСЕ элементы потока для сортировки!

---

### Архитектурные ловушки ленивости в Enterprise (Spring Boot)

#### 1. Утечка за границы транзакции (`@Transactional`)
Если репозиторий возвращает ленивый `Stream<Entity>` в контроллер:
- Транзакция Spring завершается при выходе из метода сервиса, и сессия Hibernate закрывается.
- Когда контроллер вызывает `.toList()`, ленивый стрим начинает запрашивать данные из БД через закрытую сессию, порождая фатальное исключение:
  `org.hibernate.LazyInitializationException: could not initialize proxy - no Session`.

#### 2. Смещение точки возникновения исключений (Deferred Exceptions)
Если в лямбде `map(u -> 100 / u.getDivisor())` заложена ошибка деления на ноль, исключение `ArithmeticException` возникнет **не в месте объявления стрима**, а там, где будет вызвана терминальная операция (возможно, через десятки методов в совершенно другом потоке).

## 🎯 Шпаргалка для интервью

### 30-секундный ответ
> «Lazy Evaluation — стратегия, при которой промежуточные операции не выполняют вычислений в момент объявления, а лишь строят цепочку `Sink`-обработчиков. Реальная обработка инициируется исключительно терминальной операцией. Благодаря ленивости Stream API применяет оптимизацию Loop Fusion (вертикальный проход одного элемента сквозь весь пайплайн), что исключает аллокации промежуточных коллекций и обеспечивает работу с бесконечными стримами в связке с операциями короткого замыкания (`limit`, `findFirst`).»

---

### Сравнение моделей вычисления

| Характеристика | Eager Evaluation (Коллекции) | Lazy Evaluation (Stream API) |
|---|---|---|
| **Момент старта** | Немедленно при вызове метода | При вызове терминальной операции |
| **Промежуточная память** | Создает коллекции на каждом шаге ($O(N)$) | Без промежуточных коллекций ($O(1)$) |
| **Порядок обхода** | Горизонтальный (все элементы по шагам) | Вертикальный (один элемент сквозь все шаги) |
| **Бесконечные структуры** | Не поддерживаются (вызовут OOM) | Поддерживаются через `Stream.iterate/generate` |
| **Short-Circuiting** | Невозможно без ручных циклов | Встроено (`limit`, `findAny`, `anyMatch`) |

### Топ-4 каверзных вопроса на интервью

#### 1. Что такое Loop Fusion (слияние циклов) и как оно связано с ленивостью?
- Loop Fusion — это механизм оптимизации, при котором цепочка промежуточных операций (`filter().map().peek()`) объединяется в единый цикл обхода. Вместо трех отдельных проходов по миллиону элементов с созданием промежуточных списков, рантайм берет один элемент и сразу «проталкивает» его через фильтр и маппинг в терминальный аккумулятор, сохраняя данные в кэше CPU.

#### 2. Что произойдет, если бросить исключение в `map()`, но забыть вызвать терминальную операцию?
- Ничего не произойдет. Код лямбды внутри `map()` просто **никогда не будет вызван**. Стрим останется неактивным объектом метаданных в куче и будет собран сборщиком мусора (GC) без каких-либо ошибок.

#### 3. Почему операция `sorted()` не может быть полностью ленивой?
- `sorted()` является операцией с состоянием (stateful). Чтобы узнать, какой элемент является наименьшим и должен первым пойти дальше по конвейеру, алгоритм сортировки обязан сначала полностью вычитать и буферизовать в память абсолютно все элементы источника. Поэтому `sorted()` действует как барьер синхронизации.

#### 4. В чем опасность возврата `Stream` из метода Spring Data JPA репозитория?
- JPA Stream держит открытым `ResultSet` базы данных и соединение `Connection` из пула HikariCP. Если клиентский код отложит вызов терминальной операции или забудет обернуть стрим в `try-with-resources`, соединение с БД останется заблокированным, что быстро приведет к исчерпанию пула соединений (Connection Pool Exhaustion).

---

### Типичные ошибки и Red Flags
- 🚩 Ожидание выполнения промежуточных операций без вызова терминальной операции (код «молча не работает»).
- 🚩 Возврат ленивого `Stream` из сервиса с `@Transactional` в веб-контроллер.
- 🚩 Попытка применить `sorted()` на бесконечном стриме `Stream.generate()`.
- 🚩 Размещение побочных эффектов в промежуточных операциях в расчете на их гарантированное последовательное выполнение.
