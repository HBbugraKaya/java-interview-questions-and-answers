# Как работать с Optional в Stream

---

## 🟢 Junior Level

### Краткий ответ для собеседования (30 секунд)
`Optional<T>` и `Stream<T>` спроектированы для совместной работы в функциональном стиле. Основные сценарии взаимодействия:

1. **Терминальные операции Stream возвращают `Optional`:** операции `findFirst()`, `findAny()`, `min()`, `max()`, `reduce(accumulator)` возвращают `Optional<T>`, так как результирующий поток может быть пустым.
2. **Распаковка `Stream<Optional<T>>` в плоский `Stream<T>`:** начиная с Java 9, для безопасного исключения пустых контейнеров используется метод **`.flatMap(Optional::stream)`**.
3. **Безопасное извлечение значений:** категорически запрещено вызывать `.get()` без предварительной проверки. Вместо этого используются методы `orElse(defaultValue)`, `orElseGet(Supplier)` или `orElseThrow()`.

---

### Примеры использования на Java 21

```java
import java.util.List;
import java.util.Optional;

public class OptionalStreamDemo {

    public record User(int id, String name, String email) {}

    public static void main(String[] args) {
        List<Optional<String>> rawEmails = List.of(
            Optional.of("user1@example.com"),
            Optional.empty(),
            Optional.of("user3@example.com")
        );

        // 1. Преобразование Stream<Optional<String>> -> Stream<String> (Java 9+)
        List<String> validEmails = rawEmails.stream()
            .flatMap(Optional::stream) // Пустые Optional автоматически отсеиваются!
            .map(String::toLowerCase)
            .toList();

        System.out.println("Валидные email: " + validEmails); // [user1@example.com, user3@example.com]

        // 2. Поиск с безопасным извлечением через orElse
        List<User> users = List.of(new User(1, "Иван", "ivan@mail.ru"));

        String foundName = users.stream()
            .filter(u -> u.id() == 2)
            .findFirst()
            .map(User::name)
            .orElse("Гость");

        System.out.println("Пользователь: " + foundName); // Гость
    }
}
```

## 🟡 Middle Level

### Эволюция распаковки: Java 8 против Java 9+

#### Java 8 стиль (двухэтапная фильтрация):
```java
List<String> listJava8 = rawOptionals.stream()
    .filter(Optional::isPresent)
    .map(Optional::get) // Выглядит многословно, потенциальный риск NPE при ошибке
    .toList();
```

#### Java 9+ стиль (`Optional.stream()`):
Метод `Optional.stream()` преобразует экземпляр `Optional`:
- если значение присутствует $\rightarrow$ `Stream.of(value)` (поток из 1 элемента);
- если пусто $\rightarrow$ `Stream.empty()` (пустой поток).

При вызове `.flatMap(Optional::stream)` все единичные потоки объединяются, а пустые подпотоки бесследно исчезают:
```java
List<String> listJava9 = rawOptionals.stream()
    .flatMap(Optional::stream) // Лаконично и безопасно
    .toList();
```

### Разница: `orElse()` против `orElseGet()` внутри стримов

Частая архитектурная ошибка — вычисление дефолтных значений:

```java
// ❌ ОПАСНО: orElse() ВСЕГДА выполняет аргумент, даже если значение присутствует!
String result = opt.orElse(callHeavyRemoteService());

// ✅ ПРАВИЛЬНО: orElseGet() выполняет лямбду ТОЛЬКО если Optional пуст (лениво)!
String safeResult = opt.orElseGet(() -> callHeavyRemoteService());
```

Внутри конвейера стримов передача тяжелых методов (запросов в БД, генерации токенов) в `orElse()` приводит к их холостому выполнению для каждого элемента потока.

## 🔴 Senior Level

### Архитектурные правила использования `Optional` в Enterprise

1. **`Optional` — только для возвращаемых значений:**
   Создатель `Optional` Брайан Гетц прямо подчеркивал: класс `Optional` создавался как тип возвращаемого значения для библиотечных методов, где отсутствие результата является ожидаемым нормальным сценарием (`findFirst()`, `findById()`).
2. **Антипаттерн: `Optional` в полях Entity и DTO:**
   - Класс `java.util.Optional` **не реализует интерфейс `java.io.Serializable`**.
   - Помещение `Optional` в поля JPA/Hibernate сущностей приводит к сбоям сериализации в распределенных кэшах (Redis, Hazelcast) и сессиях.
   - Увеличивает footprint: каждый `Optional` — это отдельный ссылочный объект в куче (16–24 байта).
3. **Антипаттерн: `Optional` в параметрах методов:**
   Передача `Optional<T>` в качестве аргумента метода усложняет клиентский вызов (приходится писать `foo(Optional.of(x))`) и открывает возможность передать `null` вместо самого `Optional`, что вернет проблему NPE обратно.

---

### Highload и примитивные специализации

В высоконагруженных системах (FinTech, рекламные аукционы RTB):
- Создание сотен тысяч объектов `Optional<Integer>` перегружает сборщик мусора (GC pressure).
- Для примитивных типов всегда используются специализированные стримы и контейнеры:
  `IntStream.max()` $\rightarrow$ **`OptionalInt`**
  `LongStream.findFirst()` $\rightarrow$ **`OptionalLong`**
  `DoubleStream.average()` $\rightarrow$ **`OptionalDouble`**

Они хранят значение в обычном примитивном поле `int/long/double` и логический флаг `isPresent`, не создавая объектов в куче при инлайнинге.

### Методы Java 9–11 для функциональных цепочек

```java

Optional<User> user = findInCache(id)

    .or(() -> findInExternalApi(id));

// 2. ifPresentOrElse() (Java 9+): ветвление без if-else

    () -> log.warn("Пользователь не найден")

// 3. isEmpty() (Java 11+): лаконичная инверсия isPresent()
```

## 🎯 Шпаргалка для интервью

### 30-секундный ответ
> «`Optional` и `Stream` органично дополняют друг друга. Терминальные методы стримов (`findFirst`, `reduce`, `min`) возвращают `Optional`, исключая возвраты `null`. Для превращения `Stream<Optional<T>>` в плоский `Stream<T>` в современном Java-коде используется `.flatMap(Optional::stream)`. Главное правило: `Optional` предназначен только для возвращаемых типов методов; использовать его в полях классов (особенно JPA Entity) и параметрах методов нельзя. При выборе между `orElse` и `orElseGet` всегда следует предпочитать ленивый `orElseGet` для предотвращения холостых вычислений.»

---

### Сводка методов работы с `Optional` в Stream

| Задача | Рекомендуемый подход | Чего избегать |
|---|---|---|
| Сплющить `Stream<Optional<T>>` | `.flatMap(Optional::stream)` | `.filter(o -> o.isPresent()).map(o -> o.get())` |
| Безопасный дефолт | `.orElseGet(this::calculateDefault)` | `.orElse(calculateDefault())` (холостые вызовы) |
| Выброс ошибки при отсутствии | `.orElseThrow(() -> new NotFoundEx())` | `.get()` без проверок (`NoSuchElementException`) |
| Создание из возможного `null` | `Optional.ofNullable(val)` | `Optional.of(val)` (выбросит NPE при null) |
| Примитивные стримы | `OptionalInt`, `OptionalLong` | Боксинг в `Optional<Integer>` |

### Топ-4 каверзных вопроса на интервью

#### 1. Как в Java 9+ лаконично преобразовать `Stream<Optional<T>>` в `Stream<T>` без пустых элементов?
- Вызвать метод `.flatMap(Optional::stream)`. Метод `Optional.stream()` преобразует непустой контейнер в стрим из одного элемента, а пустой — в `Stream.empty()`. Метод `flatMap` уплощает все единичные стримы в единый поток, автоматически отсеивая пустые.

#### 2. В чем разница между `.orElse(compute())` и `.orElseGet(this::compute)` внутри стрима?
- Метод `.orElse(compute())` принимает готовое значение: выражение `compute()` будет вычисляться **всегда**, даже если `Optional` содержит значение.
- Метод `.orElseGet(Supplier)` принимает ленивый интерфейс: код вычисления выполнится **только в том случае, если `Optional` действительно пуст**.

#### 3. Почему `Optional` не должен использоваться в качестве поля JPA Entity?
- Во-первых, класс `Optional` не реализует `Serializable`, что приведет к ошибкам при сериализации сущности фреймворками кэширования.
- Во-вторых, спецификация JPA/Hibernate не поддерживает сопоставление полей `Optional` с колонками таблиц БД напрямую.
- В-третьих, это создает лишние аллокации памяти в куче для каждого экземпляра сущности.

#### 4. В чем разница между `Optional.of()` и `Optional.ofNullable()`?
- `Optional.of(value)` требует строго ненулевое значение и выбрасывает `NullPointerException`, если передан `null`.
- `Optional.ofNullable(value)` безопасно обрабатывает `null`, возвращая в этом случае пустой экземпляр `Optional.empty()`.

---

### Типичные ошибки и Red Flags
- 🚩 Вызов метода `.get()` на `Optional` без предварительной проверки `isPresent()`.
- 🚩 Использование `Optional` в качестве типов полей класса или параметров методов.
- 🚩 Вызов тяжелых методов внутри `orElse()` вместо `orElseGet()`.
- 🚩 Попытка упаковать `null` через `Optional.of(null)`, вызывающая мгновенный NPE.
