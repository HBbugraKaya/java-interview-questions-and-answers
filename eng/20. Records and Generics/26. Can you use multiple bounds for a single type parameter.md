# Can you use multiple bounds for a single type parameter

**Yes, you can specify multiple bounds for a single generic type parameter** using the ampersand **`&`** intersection operator (e.g., `<T extends Number & Comparable<T>>`). This enforces that the type argument must simultaneously satisfy a class inheritance hierarchy and multiple interface contracts.

---

## 🟢 Junior Level

### Syntax and Fundamental Rules
A type parameter can be constrained by multiple bounds separated by the `&` symbol:

```java
// T must be a subclass of Number AND implement Comparable<T>
public class SortedNumberBox<T extends Number & Comparable<T>> {
    private final T value;

    public SortedNumberBox(T value) {
        this.value = value;
    }

    public boolean isGreaterThan(T other) {
        // Methods from both bounds are directly accessible:
        // doubleValue() from Number, compareTo() from Comparable
        return value.doubleValue() > 0 && value.compareTo(other) > 0;
    }
}
```

### The Two Golden Syntax Rules (JLS §4.4)
1. **At Most One Class:** Because Java enforces single class inheritance, a type parameter can have **at most one class bound**.
2. **The Class Bound Must Come First:** If a class bound is present, it **must** be declared at the first position, followed by one or more interfaces:
   ```java
   // ✅ Valid: Class listed first, followed by interface
   public <T extends Number & Runnable> void execute(T task) { ... }

   // ❌ Compilation Error: Interface cannot precede class bound
   // public <T extends Runnable & Number> void execute(T task) { ... }
   ```

## 🟡 Middle Level

### Type Erasure Mechanics: Erasure to the First Bound (JLS §4.6)
According to the Java Language Specification, when a type parameter has multiple bounds, it is erased in JVM bytecode to its **first (leftmost) bound**:

```java
public class Processor<T extends Number & Serializable> {
    public void process(T item) {
        double val = item.doubleValue(); // Method from Number (First Bound)
        save(item);                      // Method expecting Serializable (Second Bound)
    }

    private void save(Serializable s) { ... }
}
```

#### What `javac` Emits in Bytecode:
1. In method signatures and field descriptors, `item` erases to `java.lang.Number`:
   ```bytecode
   public void process(java.lang.Number item);
   ```
2. Invocations of `item.doubleValue()` are executed directly via `invokevirtual` on `java.lang.Number`.
3. When `item` is passed to `save(Serializable)`, the compiler automatically synthesizes an explicit type cast:
   ```bytecode
   aload_1
   checkcast     #4 // class java/io/Serializable
   invokevirtual #5 // Method save:(Ljava/io/Serializable;)V
   ```

> [!TIP]
> **Bytecode Micro-Optimization:** When bounding by multiple interfaces (with no class bound), place the interface whose methods are called most frequently as the **first bound**. This minimizes the number of synthetic `checkcast` instructions generated by `javac`.

## 🔴 Senior Level

### Intersection Types in Cast Expressions (Distributed Computing)
Since Java 8, multiple bounds can be used in explicit cast expressions to create **Intersection Types** (JLS §15.16):

```java
// Casts a lambda to an intersection of Runnable AND Serializable:
Runnable task = (Runnable & Serializable) () -> System.out.println("Processing distributed job");
```

#### Real-World Production Use Case: Apache Spark / Flink
In distributed processing frameworks (Apache Spark, Apache Flink, Hazelcast), computations are submitted as lambdas and serialized over TCP sockets to remote worker nodes. 
- A standard Java lambda `() -> ...` does not implement `java.io.Serializable` by default. Passing it across a network cluster throws a runtime `NotSerializableException`.
- Applying an intersection cast `(Runnable & Serializable)` instructs the compiler to generate a lambda class that implements both interfaces, enabling network serialization without declaring boilerplate wrapper interfaces.

### Signature Conflicts in Multiple Bounds
If multiple interfaces in a bound declare methods with conflicting signatures, the compiler halts with an error:

#### 1. Incompatible Return Types
```java
interface ReaderA { String read(); }
interface ReaderB { Integer read(); }

// ❌ Compilation Error: methods have unrelated return types
class Service<T extends ReaderA & ReaderB> { }
```
No Java type can implement both interfaces simultaneously.

#### 2. Conflicting Default Methods
```java
interface Alpha { default void execute() { System.out.println("A"); } }
interface Beta  { default void execute() { System.out.println("B"); } }

// ❌ Compilation Error: types Alpha and Beta are incompatible;
// both define execute() with identical signature
class Worker<T extends Alpha & Beta> { }
```

## 4 Tricky Questions

### 1. Can you specify multiple bounds on wildcards, such as `List<? extends Number & Comparable>`?
**Answer:** **No, wildcards do not support multiple bounds (JLS §4.5.1).** 
The syntax `<? extends A & B>` causes an immediate compilation error. Multiple bounds are permitted exclusively on **Type Parameter declarations** (`<T extends A & B>`). 

If a method needs to accept a collection whose elements satisfy multiple constraints, declare a generic method with a named type parameter:
```java
// ❌ Compilation Error:
public void process(List<? extends Number & Comparable<?>> list)

// ✅ Idiomatic Solution:
public <T extends Number & Comparable<?>> void process(List<T> list)
```

### 2. Does the ordering of interface bounds matter when no class bound is present (`<T extends A & B>` vs `<T extends B & A>`)?
**Answer:** **Yes, it significantly impacts the compiled bytecode and binary compatibility.** 
Because type erasure replaces $T$ with its **first bound**:
- `<T extends Comparable<?> & CharSequence>` erases to `Comparable`.
- `<T extends CharSequence & Comparable<?>>` erases to `CharSequence`.

Changing the order alters the compiled method descriptors in the `.class` file, which can break binary backward compatibility for downstream libraries and determines where the compiler emits `checkcast` instructions.

### 3. Can you declare a local variable of an intersection type?
**Answer:** Yes, starting in Java 10 using local variable type inference with **`var`**. 
Prior to Java 10, Java syntax provided no way to declare an intersection type variable without a generic helper method. With `var`, the compiler infers the exact, non-denotable intersection type:
```java
var task = (Runnable & Serializable) () -> System.out.println("Run");
task.run(); // Accessible via Runnable
boolean isSer = task instanceof Serializable; // Accessible via Serializable
```

### 4. How can you inspect all bounds of a generic type parameter at runtime via Reflection?
**Answer:** Using `TypeVariable.getBounds()`:
```java
TypeVariable<?>[] typeParams = SortedNumberBox.class.getTypeParameters();
Type[] bounds = typeParams[0].getBounds();
for (Type bound : bounds) {
    System.out.println(bound.getTypeName());
}
// Outputs:
// java.lang.Number
// java.lang.Comparable<T>
```
While types are erased from method bodies, class and type parameter bounds are permanently recorded in the `.class` file's constant pool under the `Signature` attribute.

## 🎯 Interview Cheat Sheet

- **Syntax:** Multiple bounds are linked using `&`: `<T extends ClassA & InterfaceB & InterfaceC>`.
- **First Element Rule:** At most **one class** is permitted, and it **must be listed first**.
- **Type Erasure:** $T$ erases to the **first leftmost bound**. Accessing methods of subsequent bounds triggers compiler-generated `checkcast` instructions.
- **Wildcard Prohibition:** `<? extends A & B>` is illegal syntax. Use a generic method with `<T extends A & B>` instead.
- **Distributed Computing:** Intersection casts `(Runnable & Serializable) () -> ...` enable serializing lambdas in Apache Spark and Flink.
- **Java 10 `var`:** Enables local variables to hold intersection types without losing access to interface members.
- **Reflection:** Bounds are preserved in the `Signature` attribute and accessible via `TypeVariable.getBounds()`.
