# Чому String реалізує Comparable та CharSequence

---

## 🟢 Junior Level

Клас `String` реалізує інтерфейси `Comparable<String>` та `CharSequence`, вирішуючи два фундаментальні архітектурні завдання:
- **`Comparable<String>`** надає рядкам **природний порядок сортування (Natural Ordering)**. Це дозволяє порівнювати рядки між собою через метод `compareTo()`, автоматично сортувати колекції рядків (`Collections.sort()`) і використовувати рядки як ключі в упорядкованих структурах даних (`TreeSet`, `TreeMap`).
- **`CharSequence`** визначає рядок як **доступну тільки для читання послідовність символів**. Це базовий інтерфейс-абстракція, що об'єднує різні текстові типи (`String`, `StringBuilder`, `StringBuffer`, `CharBuffer`), що дозволяє писати універсальні методи обробки тексту без прив'язки до конкретного класу.

### Суть у 30 секундах
1. Завдяки `Comparable`: рядки можна порівнювати за принципом «менше / рівно / більше» та сортувати за алфавітом (за кодами Unicode).
2. Завдяки `CharSequence`: будь-який метод, що приймає `CharSequence` (наприклад, регулярні вирази `Pattern.matcher()`), може працювати зі `String`, `StringBuilder` або `CharBuffer` напряму **без зайвих алокацій пам'яті** на виклики `.toString()`.

```java
// 1. Використання Comparable<String>:
List<String> fruits = new ArrayList<>(List.of("Orange", "Apple", "Banana"));
Collections.sort(fruits); 
// Результат відсортовано за алфавітом: ["Apple", "Banana", "Orange"]

// 2. Використання CharSequence:
void printLength(CharSequence seq) {
    System.out.println("Довжина: " + seq.length());
}

printLength("Hello");                 // Передаємо незмінний String
printLength(new StringBuilder("Hi")); // Передаємо змінний StringBuilder без .toString()!
```

## 🟡 Middle Level

### Інтерфейс `Comparable<String>`: Лексикографічне порівняння
Метод `compareTo(String anotherString)` порівнює рядки **лексикографічно** (за числовими значеннями кодів символів Unicode):
- Повертає **від'ємне число**, якщо викликаючий рядок менший за аргумент.
- Повертає **нуль**, якщо рядки еквівалентні за вмістом (`str1.equals(str2) == true`).
- Повертає **додатне число**, якщо викликаючий рядок більший за аргумент.

```java
System.out.println("apple".compareTo("banana")); // Від'ємне ('a' < 'b')
System.out.println("cat".compareTo("car"));       // Додатне ('t' > 'r')
System.out.println("test".compareTo("test"));     // 0 (рядки рівні)
System.out.println("app".compareTo("apple"));     // Від'ємне (-2, різниця довжин)
```

**Критичний нюанс:** Лексикографічне порівняння **не враховує правила людської мови (Locale)**. Символ `'a'` (код 97) більший за символ `'A'` (код 65), тому за `compareTo` великі літери завжди йдуть раніше малих, а літера `'є'` чи `'і'` в українській кирилиці може опинитися не на своєму алфавітному місці через розподіл кодових точок Unicode. Для алфавітного сортування з урахуванням мови використовується клас `java.text.Collator`.

### Інтерфейс `CharSequence`: Поліморфізм та Zero-Allocation
Інтерфейс `CharSequence` задає мінімальний контракт для послідовностей символів:
- `int length()` — довжина послідовності.
- `char charAt(int index)` — отримання символу за індексом.
- `CharSequence subSequence(int start, int end)` — отримання фрагмента.
- `default IntStream chars()` / `codePoints()` (Java 8+) — потоки кодів символів.
- `default boolean isEmpty()` (Java 15+) — перевірка на порожнечу.
- `static int compare(CharSequence cs1, CharSequence cs2)` (Java 11+) — лексикографічне порівняння будь-яких `CharSequence`.

**Навіщо використовувати `CharSequence` у параметрах методів?**
Якщо ваш метод тільки читає текст (наприклад, валідація `StringUtils.hasText(CharSequence str)`), оголошення аргументу як `CharSequence` дозволяє викликаючому коду передавати `StringBuilder` напряму без проміжного створення `String` через `.toString()`, заощаджуючи десятки мегабайтів алокацій у купі.

## 🔴 Senior Level

### Роль `Comparable` у захисті `HashMap` від колізійних DoS-атак (Java 8+)
У Java 8 внутрішню будову `HashMap` було кардинально перероблено:
1. У разі виникнення понад 8 колізій в одному кошику зв'язаний список перетворюється на збалансоване червоно-чорне дерево (**Red-Black Tree, `TreeNode`**).
2. **Як дерево впорядковує вузли?**
   Якщо ключі реалізують `Comparable`, дерево порівнює їх через виклик `((Comparable)k1).compareTo(k2)`.
3. **Захист від DoS:** Якби `String` не реалізовував `Comparable`, пошук у деревоподібному кошику вимагав би складного і повільного tie-breaking вирішення через `System.identityHashCode`. Реалізація `Comparable` у `String` гарантує, що навіть у разі атаки мільйонами рядків з однаковим `hashCode` час пошуку суворо обмежений **$O(\log N)$**, а не деградує до $O(N)$.

### Векторизація `compareTo` в HotSpot C2 (SIMD Intrinsics)
У сучасних версіях Java (HotSpot) методи `StringLatin1.compareTo` та `StringUTF16.compareTo` позначені анотацією `@IntrinsicCandidate`:
```java
// OpenJDK String.java
public int compareTo(String anotherString) {
    byte v1[] = value;
    byte v2[] = anotherString.value;
    byte coder = coder();
    if (coder == anotherString.coder()) {
        return isLatin1() ? StringLatin1.compareTo(v1, v2)
                          : StringUTF16.compareTo(v1, v2);
    }
    return isLatin1() ? StringLatin1.compareToUTF16(v1, v2)
                      : StringUTF16.compareToLatin1(v1, v2);
}
```
Компілятор C2 компілює цей метод із використанням процесорних векторних інструкцій:
- Процесор завантажує по 32 або 64 байти з обох рядків у векторні регістри AVX-2 / AVX-512.
- Інструкція `VPXOR` знаходить першу відмінність за 1 такт.
- Якщо рядки ідентичні, результат повертається як різниця довжин: `v1.length - v2.length`.
- Посимвольний перебір запускається лише у разі неспівпадіння всередині конкретного 32-байтового блоку.

### Еволюція `StringBuilder`: чому в Java 11 додали `Comparable`
Довгий час на співбесідах ставили каверзне запитання: «Чому `String` implements `Comparable`, а `StringBuilder` — ні?».
- **Історична відповідь (Java 1.0 – 10):** `StringBuilder` мутабельний. Зміна об'єкта, поміщеного в `TreeSet` або `TreeMap`, руйнує структуру бінарного дерева пошуку.
- **Сучасна реальність (починаючи з Java 11, JEP 329):** Починаючи з Java 11, клас `StringBuilder` (і `StringBuffer`) **також реалізує `Comparable<StringBuilder>`**! Це було зроблено для зручності порівняння вмісту буферів. Проте `StringBuilder` як і раніше **не перевизначає методи `equals()` та `hashCode()`** (вони успадковуються від `Object`), тому його природний порядок через `compareTo` **не узгоджується з `equals`**, і зберігати мутабельні `StringBuilder` у `TreeSet` категорично не рекомендується.

## 4 Tricky Questions

### 1. Чи узгоджується `String.compareTo()` з методом `String.equals()` (Contract Consistency)?
**Відповідь:**
**Так, суворо узгоджується.**
Специфікація `Comparable` рекомендує, щоб відношення `(x.compareTo(y) == 0) == (x.equals(y))` виконувалося для всіх об'єктів класу. Для класу `String` ця умова виконується **завжди**:
Якщо два рядки мають однакову довжину і однакові символи, метод `compareTo()` гарантовано повертає `0`, а метод `equals()` гарантовано повертає `true`. Це дозволяє безпечно використовувати `String` у будь-яких колекціях, заснованих як на гешуванні (`HashSet`, `HashMap`), так і на порівнянні (`TreeSet`, `TreeMap`).

### 2. Чи реалізує `StringBuilder` інтерфейс `Comparable` у Java 17/21 і чи можна використовувати його в `TreeSet`?
**Відповідь:**
- **Так, реалізує.** Починаючи з **Java 11**, клас `StringBuilder` реалізує `Comparable<StringBuilder>`. Код `treeSet.add(new StringBuilder("abc"))` успішно скомпілюється і виконається.
- **Але робити це вкрай небезпечно:**
  1. `StringBuilder` не перевизначає `equals()`, тому `sb1.compareTo(sb2) == 0` не означає `sb1.equals(sb2)`.
  2. Якщо після додавання в `TreeSet` викликати `sb.append("xyz")`, позиція елемента в червоно-чорному дереві порушиться. Дерево виявиться зламаним: метод `treeSet.contains(sb)` поверне `false`, а видалити чи знайти елемент стане неможливо.

### 3. Чому код `"єнот".compareTo("яблуко")` або `"ёлка".compareTo("яблоко")` може повертати неочікуваний результат порівняно з алфавітним порядком мови?
**Відповідь:**
Тому що метод `String.compareTo()` виконує **технічне лексикографічне порівняння за кодами Unicode**, а не лінгвістичне сортування за правилами мови.
У таблиці Unicode специфічні символи кирилиці можуть перебувати за межами основного суцільного блоку літер алфавіту (наприклад, літера `'ё'` має код `U+0451` (1105), тоді як діапазон від `'а'` до `'я'` — від `U+0430` (1072) до `U+044F` (1103)).
Код символу з іншої частини діапазону призводить до того, що `compareTo()` визнає слово більшим або меншим всупереч алфавіту. Для коректного мовного сортування потрібно завжди використовувати **`java.text.Collator`** із зазначенням потрібної локалі (`Locale`).

### 4. У чому різниця між `CharSequence.subSequence()` та `String.substring()`?
**Відповідь:**
- Метод `String.substring(start, end)` повертає строго екземпляр класу `java.lang.String`.
- Метод `CharSequence.subSequence(start, end)` є інтерфейсним методом і повертає тип `CharSequence`. У класі `String` метод `subSequence()` просто викликає `this.substring(start, end)`. Проте в інших реалізаціях (наприклад, `CharBuffer` або кастомних `StringView`) `subSequence()` може повертати легковажний зріз (Slice) **взагалі без алокації нового об'єкта і без копіювання масиву даних**, забезпечуючи Zero-Copy обробку тексту.

## 🎯 Шпаргалка для інтерв'ю

### 30-секундна відповідь
> «`String` реалізує `Comparable<String>` для забезпечення природного лексикографічного порядку сортування, що дозволяє автоматично сортувати рядки у списках, використовувати їх у `TreeSet`/`TreeMap` і захищає `HashMap` від колізійних атак через збалансовані дерева (Java 8+). Інтерфейс `CharSequence` являє собою абстракцію незмінної послідовності символів, що надає поліморфізм: методи бібліотек (наприклад, `Pattern.matcher` або парсери) можуть приймати `CharSequence`, дозволяючи передавати `String`, `StringBuilder` або `CharBuffer` напряму без зайвих алокацій пам'яті».

### Ключові тези для Senior-інтерв'ю
1. **Comparable Contract:** `(x.compareTo(y) == 0) == x.equals(y)` виконується суворо.
2. **HashMap Tree Bins:** `Comparable` дозволяє `TreeNode` в `HashMap` сортувати вузли при колізіях за $O(\log N)$, захищаючи JVM від DoS-атак.
3. **SIMD Intrinsics:** C2 компілятор замінює посимвольний цикл `compareTo` на векторні інструкції AVX-512, порівнюючи по 32/64 байти за такт.
4. **`StringBuilder` у Java 11+:** Починаючи з Java 11, `StringBuilder implements Comparable`, але зберігати його в `TreeSet` не рекомендується через мутабельність та невідповідність `equals()`.
5. **Locale vs Unicode:** `compareTo()` порівнює числові кодові точки Unicode; для природних мов обов'язковий `java.text.Collator`.

### Червоні прапорці (Чого говорити категорично не можна)
- ❌ Стверджувати, що `compareTo()` вміє сортувати рядки з урахуванням правил мовного алфавіту.
- ❌ Говорити у 2024 році, що «`StringBuilder` не реалізує `Comparable`» (у Java 11+ реалізує).
- ❌ Заявляти, що `CharSequence` — це мутабельний клас (це інтерфейс послідовності символів тільки для читання).
- ❌ Використовувати `String` у сигнатурах методів утилітарного парсингу, де достатньо `CharSequence`.
